## 2. 部署配置（Options）

### 2.1 声明与注册

```csharp
// Sample.Infrastructure
public sealed class SampleImportOptions
{
    public const string Section = "Modules:Sample:Import";

    [Range(1, 10_000)] public int BatchSize { get; init; } = 200;
    [Required, Url]    public string PartnerEndpoint { get; init; } = "";
}

// SampleModule.AddServices
services.AddKmicOptions<SampleImportOptions>(SampleImportOptions.Section);
```

| 约定 | 说明 |
|---|---|
| 分节 | 框架：`Kmic:{能力}`（如 `Kmic:Messaging`）；模块：`Modules:{模块}:{用途}`；宿主级：`Roles`、`Database` 等少数顶层项 |
| 注册 | 只能用 `AddKmicOptions<T>`：绑定 + DataAnnotations + 可选 `IValidateOptions<T>` + `ValidateOnStart()`。启动时任何一项不合法 → 拒绝启动，错误信息列出全部问题 |
| 类型 | `sealed class`，属性 `init`；有安全默认值的写默认值，没有的标 `[Required]` |
| 所在层 | Options 类放 Infrastructure（技术参数）；Application 需要的少数参数通过 Application 中定义的接口暴露，避免 Application 依赖配置结构 |
| 读取 | 注入 `IOptions<T>`；禁止注入 `IConfiguration` 自行读取（BannedApiAnalyzers，宿主与框架基础设施除外） |
| 文档 | 启动时把全部已注册的 Options 分节、类型、默认值输出为配置清单（开发环境 `GET /dev/config-schema`），运维手册据此生成 |

### 2.2 配置源与环境

按 .NET 标准顺序，后者覆盖前者：`appsettings.json` → `appsettings.{Environment}.json` → User Secrets（仅开发）→ 环境变量（`Modules__Sample__Import__BatchSize`）→ 命令行。

- 密钥只能来自 User Secrets（开发）或生产密钥源（ADR-0016 待决），**不得出现在 `appsettings*.json` 中**：CI 用密钥扫描检查仓库；启动时框架检查已标记 `[Secret]` 的属性在非开发环境中不是来自 JSON 文件（配置提供程序可追溯来源）。
- 生产密钥存储无论选 Docker Secrets 还是 Vault，都以 .NET 配置提供程序接入；应用代码只读 `IOptions<T>`，切换存储不改代码。
- `[Secret]` 属性在配置清单、日志、诊断端点中一律显示为 `***`。
- 生产密钥源为阿里云 KMS 凭据管家，部署时写入 `/run/secrets` 下的只读文件，宿主以 `AddKeyPerFile` 读取；不得用环境变量直接传递密钥值（09 D5）。

### 2.3 D1 部署配置能否在运行中生效

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 启动时绑定并校验，运行中不变（`IOptions<T>`）；改了重启** | 禁止模块使用 `IOptionsMonitor` / `IOptionsSnapshot` | 行为确定：一个进程从头到尾用同一份配置；校验只在启动时发生，不会出现“运行中读到非法配置” | 改部署配置需要重启容器（滚动重启，不中断服务） |
| B 允许热更新（`IOptionsMonitor`） | 文件或配置中心变化后自动生效 | 不用重启 | 每个使用方都要处理“值在中途变化”；热更新的值不经过启动校验；多实例生效时间不一致——这正是旧系统运行时改配置的问题换个形式 |

- **决定（已确认，2026-11-04）**：A。例外只有日志级别（Serilog 的级别切换由框架统一处理，不涉及业务代码）。
- **理由**：需要在运行中调整、并且要全实例一致生效的参数，本来就该是系统设置（第 6 节），有权限、有校验、有历史；部署配置只放技术参数。
- **取舍**：调整技术参数要重启。

## 3. 缓存的基本约定

### 3.1 组件

- 业务代码只使用 .NET 的 `HybridCache`（ADR-0016 第 2 条），框架在 `BuildingBlocks.Infrastructure` 中统一配置：
  - 单实例：只有本地缓存（L1）；
  - 多实例：配置 `Cache:Redis:ConnectionString` 后启用 Redis 作为 L2，不改代码；
  - 序列化使用 `KmicJsonOptions`（05-06 第 5 节），缓存值必须是不可变的 `record` 或基础类型。
- 框架在其上提供少量包装：键与标签构造器、提交后失效、跨实例失效广播（D2）、引用查询缓存（D5）。不再提供第二套缓存抽象。

### 3.2 键与标签

| 项 | 规范 | 例子 |
|---|---|---|
| 键 | `{模块}:{对象}:{标识…}`，标识中的版本号写在最后 | `Identity:RoleSnapshot:{roleId}:{version}`（完整的角色授权快照，05-05 第 4.3 节）、`Configuration:Dictionary:{type}` |
| 标签 | `{模块}:{对象}` 表示一类；`{模块}:{对象}:{id}` 表示一条 | `Configuration:Dictionary`、`Customer:Ref:{id}` |
| 构造 | 只能通过各模块的 `CacheKeys` 静态类生成（模板提供），禁止在调用处拼字符串；这些静态类内部用框架的 `CacheKey.Of(模块, 对象, 标识…)`：标识按不变区域格式化，段内出现 `:` 即抛异常 | `ConfigurationCacheKeys.Dictionary(type)` |
| 前缀 | Redis 中统一加 `kmic:{环境}:` 前缀，避免多个环境共用 Redis 时串数据 | — |

- 架构测试：缓存键的第一段必须是本模块名（框架键用 `Kmic:`）；`HybridCache` 的调用只能出现在模块的 Infrastructure 与查询处理器中。

### 3.3 过期

| 类别 | 本地 L1 | 分布式 L2 | 说明 |
|---|---|---|---|
| 版本键（内容不可变） | 1 小时 | 1 天 | 版本变即换键，过期只为回收内存 |
| 标签失效（配置类） | 10 分钟 | 1 小时 | 正常情况下由失效即时生效，过期只是兜底 |
| 引用查询 | 5 分钟 | 30 分钟 | 由快照事件驱动失效（D5），过期兜底 |

以上为默认值，均可在 `Kmic:Cache` 中按类别调整（`待确认`：上线后按命中率调整）。

版本键的前提是版本号只增不减。数据库按时间点恢复后版本号会回退，恢复后必须清空全部缓存：重启应用实例；启用 L2 后同时清空 Redis（09 第 11.2 节）。

## 4. 什么能缓存、怎样失效

### 4.1 分类规则

| 类别 | 例子 | 失效方式 | 能否缓存 |
|---|---|---|---|
| 按版本不可变的内容 | 角色权限点集合、组织树快照（05-05） | 换键（版本号在键中），无需失效 | 能，首选 |
| 读多写少的全局配置 | 字典、系统设置、偏好的系统 / 角色层、菜单定义 | 写入命令提交后按标签失效（4.2）+ 跨实例广播（D2） | 能 |
| 引用显示信息 | `ReferenceInfo`（05-07 D3） | 源聚合发布快照事件时自动失效（D5） | 能，框架提供 |
| 随用户数据范围变化的查询结果 | 列表、`CallerScoped` 查询、统计 | — | **不能**：结果依赖调用者的权限，缓存会把一个人的可见数据给另一个人 |
| 会话、用户状态、当前角色、授予 | 访问上下文的状态部分 | — | **不能**（ADR-0026：每个请求查库） |
| 业务单据 | 聚合、详情 | — | 不缓存（命令必须读最新数据；详情查询足够快） |

- 判断标准（写入编码规范）：**数据变化后，用户看到旧值一会儿是否可以接受？结果是否因人而异？** 前者否或后者是，就不缓存。

### 4.2 提交后失效

```csharp
// 写入命令的处理器
public async ValueTask<Result> Handle(UpdateDictionaryItemCommand command, CancellationToken cancellationToken)
{
    …   // 修改字典项
    afterCommit.InvalidateTags(ConfigurationCacheKeys.DictionaryTag(command.Type));   // 05-02 第 6.3 节
    return Result.Success();
}
```

- 失效在**提交成功之后**执行（05-02 D6）：提交前清除会被并发请求用旧数据重新填入。
- `InvalidateTags` 是 `IAfterCommit` 的成员（扩展方法拿不到缓存服务）：同一事务登记的标签合并去重，提交后做两件事：本实例 `RemoveByTagAsync`（含 L2）；向其他实例广播（D2）。
- 失效失败只记 Warning（05-02 D6 的“可丢失动作”），兜底是 3.3 的过期时间。

### 4.3 D2 多实例时，其他实例的本地缓存怎么失效

HybridCache 启用 Redis 后，L2 是共享的，但**每个实例的本地 L1 各自独立**。实例 A 删除标签后，实例 B 的 L1 仍持有旧值，直到 L1 过期（`待确认`：.NET 10 HybridCache 是否已内置跨实例 L1 失效，锁定版本时核实；若已内置则采用内置机制，以下选项只在未内置时生效）。

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 只靠 L1 短过期 | L1 设为 30～60 秒 | 无额外机制 | 修改字典、设置后，其他实例最长 1 分钟仍是旧值，“改了不生效”的反馈会出现；过期短又降低命中率 |
| **B 用 PG `NOTIFY` 广播失效** | `InvalidateTags` 在本实例失效后执行 `pg_notify('kmic_cache', '<标签列表>')`；每个实例的监听连接（05-07 D8 已有）收到后在本地 `RemoveByTagAsync` | 毫秒级全实例生效；不依赖 Redis，单机多实例、未启用 Redis 时同样成立；复用已有的监听连接 | 通知在连接断开时可能丢失（重连后清空全部本地缓存兜底）；`NOTIFY` 载荷上限 8000 字节，标签多时分批 |
| C 换用自带广播的缓存库（如 FusionCache） | 替换 HybridCache | 机制现成 | 违背 ADR-0016 的选型；多一个第三方依赖 |

- **决定（已确认，2026-11-04）**：B。监听连接断开重连后，框架清空本实例全部 L1（宁可多查一次库，不可读到旧值）。监听循环的写法见 05-07 第 6.4 节（专用线程上的同步 `Wait(超时)`）。
- **理由**：配置类数据的修改频率很低，但“改了马上生效”是用户最在意的；复用已有监听连接，成本很小。
- **取舍**：多一个通知通道；只跑 Api 的实例也要持有一个监听连接（05-08 D2 的连接预算中已含）。

### 4.4 D5 引用查询是否由框架统一缓存

列表页每次都要解析客户名、人员名（05-07 D3 的 `Reference` 查询），是全系统调用最频繁的跨模块查询。

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 不缓存，按需由各模块自行处理 | — | 无额外机制 | 每个列表请求都要对各个提供方发起查询；各模块各写一套缓存，失效规则不一 |
| **B 框架提供引用缓存，按快照事件自动失效** | 提供方的 `Reference` 适配器使用框架的 `ReferenceCache.ResolveAsync(ids, fetchMissing)`：逐个 ID 缓存，键 `{模块}:Ref:{聚合}:{id}`，标签 `{模块}:Ref:{id}`；05-07 拦截器 5 写入 `ISnapshotEvent` 时，自动登记“提交后失效该 ID 的标签” | 命中率高（名称很少变）；失效与“数据变了”严格同步，不需要每个模块记得写；只有没命中的 ID 才查库 | 只对发布快照事件的聚合生效；按 ID 粒度缓存，批量取时要多次读本地缓存（内存操作，开销可忽略） |

- **决定（已确认，2026-11-04）**：B。没有快照事件的聚合不得使用 `ReferenceCache`（启动校验：`Reference` 查询所属聚合必须有 `{聚合}Changed` 事件，否则只能不缓存）。
- **理由**：`ReferenceInfo` 只有名称、编码、状态，内容小、变化少、不因人而异，是最适合缓存的数据；用快照事件驱动失效，正好复用 05-07 已有的“数据变了”信号。
- **取舍**：引用缓存与快照事件绑定，两者的规则要一起记住。

### 4.5 禁止事项（架构测试与分析器）

| 禁止 | 检查方式 |
|---|---|
| `static` 字段或属性保存可变数据或用户相关数据 | 架构测试：模块程序集中非 `readonly` 的静态字段、`static` 集合字段一律报错（常量、`static readonly` 不可变对象除外） |
| 使用 `IMemoryCache`、`IDistributedCache`、`HttpRuntime` 风格的自建缓存 | BannedApiAnalyzers（框架基础设施除外） |
| 缓存列表、`CallerScoped` 查询结果 | 代码评审；查询处理器中调用 `HybridCache` 时需在评审中说明属于 4.1 的哪一类 |
| 缓存值为可变类型 | 架构测试：`GetOrCreateAsync<T>` 的 `T` 必须是 `record` / 基础类型 / 不可变集合 |

## 5. 字典

### 5.1 D3 字典类型由谁定义

字典 = 业务人员维护的候选值（行业、客户等级、单位等）。与智能枚举的边界：**代码要按取值做不同处理的，用智能枚举（05-01）；代码只存储、显示、筛选的，用字典。**

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 字典类型由代码声明，字典项在界面维护** | 模块中声明 `[DictionaryType("Sample.Industry", "行业")]`；启动时登记到 Configuration；项由管理员维护 | 代码引用的类型一定存在，不会被误删；类型归属模块明确；类型名进入 OpenAPI，前端可生成常量 | 新增一个字典类型需要发版 |
| B 类型和项都在界面维护 | 管理员随时新建类型 | 最灵活 | 代码按字符串引用类型，类型被改名或删除时运行时才出错；无人知道哪个类型被谁使用 |

- **决定（已确认，2026-11-04）**：A。类型登记与权限点同步同一机制（启动任务，内容哈希，代码中删除的类型标记退役，见 05-05 D2 的处理方式）。
- **取舍**：新增字典类型要发版；字典项的增改不需要。

### 5.2 结构

Configuration 模块：

| 表 | 主要列 |
|---|---|
| `DictionaryType` | `Code`（如 `Sample.Industry`，主键）、`DisplayName`、`OwnerModule`、`IsHierarchical`、`Status`（`Active` / `Retired`） |
| `DictionaryItem`（`DictionaryType` 的子实体，用类型的 `ConcurrencyVersion` 控制并发；单类型项数上限默认 2000） | `Id`、`TypeCode`、`Code`（同类型内唯一，**创建后不可修改**）、`Name`、`ParentCode`（层级字典）、`SortOrder`、`Status`（`Active` / `Disabled`）、审计字段 |

- 业务数据只保存字典项的 `Code`（字符串，长度上限 50），不保存名称，也不保存 `Id`。
- 字典项**不删除只停用**：停用后历史数据显示时标 `[已禁用]`，新数据不可选（ADR-0012 第 3 条）。
- 不提供“附加属性”列：需要额外属性的候选值，说明它有业务含义，应建业务表或智能枚举（ADR-0016“不预建空表”）。
- 维护命令全部 `[Audited]`，权限点 `Configuration.Dictionary.Manage`。

### 5.3 读取与校验

```csharp
// Configuration.Contracts —— 05-07 D3：Reference 类之外的第三种只读形态，结果与调用者无关
public interface IDictionaries
{
    ValueTask<DictionarySnapshot> GetAsync(string typeCode, CancellationToken ct);              // 含停用项，带状态
    ValueTask<Result> EnsureSelectableAsync(string typeCode, string itemCode, CancellationToken ct); // 存在且启用
}
```

- 读取经缓存（键 `Configuration:Dictionary:{type}`，标签 `Configuration:Dictionary`），维护命令提交后失效并广播（D2）。
- 命令中对用户输入的字典编码调用 `EnsureSelectable`，失败返回 `Configuration.DictionaryItemNotSelectable`（422）。
- 字典内容对所有登录用户可见（候选值不是业务数据），`IDictionaries` 声明为 `[ContractQuery(Reference)]` 的同类：不检查权限点、不套数据范围。已在 05-07 D3 的启动校验白名单中登记（返回类型不是 `ReferenceInfo`）。

### 5.4 D4 列表与详情如何显示字典名称

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 接口只返回编码，前端按字典翻译** | 前端启动后按需拉取字典（`GET /api/v1/configuration/dictionaries?types=a,b`，带 `ETag`），本地缓存；表格列声明字典类型即可显示名称和停用标记 | 接口响应小；名称修改后无需重算任何数据；与智能枚举“只返回编码”的做法一致（05-06） | 前端要实现字典翻译组件；需要名称的后端场景（导出、通知内容）要自己翻译 |
| B 后端把编码翻译成名称一起返回 | 每个 DTO 同时有 `IndustryCode`、`IndustryName` | 前端直接显示 | 每个查询都要多一步翻译；同一含义两个字段；按名称排序筛选的错觉（实际只能按编码） |

- **决定（已确认，2026-11-04）**：A。后端需要名称的场景使用 `IDictionaries.Get` 翻译，框架提供导出列的“字典列”声明（05-08 第 6.10 节导出复用）。
- **取舍**：前端多一个通用组件；接口文档中字典编码字段需标注字典类型（OpenAPI 扩展 `x-dictionary: Sample.Industry`，由属性上的 `[Dictionary("Sample.Industry")]` 生成）。

## 6. 系统设置

### 6.1 声明

```csharp
// Sample.Application —— 设置由代码声明：键、类型、默认值、取值范围、修改权限
[SystemSetting("Sample.Approval.Threshold", "审批金额阈值", Group = "审批", EditPermission = SamplePermissions.ManageSettings)]
public sealed record ApprovalThreshold(decimal Value) : ISystemSetting<ApprovalThreshold>
{
    public static ApprovalThreshold Default => new(50_000m);
    public static Result Validate(ApprovalThreshold s) =>
        s.Value is > 0 and <= 10_000_000 ? Result.Success() : SampleErrors.ThresholdOutOfRange;
}
```

| 规则 | 说明 |
|---|---|
| 定义在代码 | 键以本模块名开头、唯一；值类型为 `sealed record`、属性只能 `init`，成员限于 `bool`、`int`、`long`、`decimal`、`double`、`string`、`Guid`（如人员 ID）、`DateOnly`、`TimeOnly`、`DateTimeOffset`、`TimeSpan`、它们的可空形式与数组 |
| 默认值 | 必须提供；数据库中没有值时使用默认值，新环境开箱可用。由 `ISystemSetting<T>` 的静态抽象成员 `Default` 保证（不写编译不过），启动时还检查默认值能通过自身的 `Validate` |
| 校验 | 静态抽象成员 `Validate`，写入时执行 |
| 修改权限 | 每项声明修改所需权限点，由 `Setting` 资源策略执行（命令声明基础权限点 `Configuration.Setting.View`，策略再检查该设置的修改权限点）；查看设置的界面需 `Configuration.Setting.View`；清除代码里已不存在的设置值需 `Configuration.Setting.Manage`（敏感） |
| 界面元数据 | 成员可标 `[SettingField("显示名", Unit = "元")]`（选人类成员标类型），管理页据此按成员类型生成表单；超出上述成员类型的复杂结构仍按 ADR-0016“需求出现再扩展” |
| 不放什么 | 密钥（第 2.2 节）；审批人这类“谁有权处理”的信息——应是权限点 / 角色 + 数据范围（05-05），不是设置 |

### 6.2 存储

Configuration 模块：

| 表 | 主要列 |
|---|---|
| `SystemSettingValue` | `Key`（主键）、`Value jsonb`、`ConcurrencyVersion`、审计字段 |
| `SystemSettingChange` | `Id`、`Key`、`OldValue`、`NewValue`、`Reason`（必填）、`ChangedBy`、`ChangedAt`、`TraceId`；只追加（05-09 D7 的 `REVOKE` 适用） |

- 定义的目录在启动时由各模块汇总到内存（与用例目录同一机制），不同步到数据库；数据库只存被修改过的值。
- 代码中删除的设置：其值行保留但不再读取，管理界面标为“已不存在”，可手动清除。
- 修改命令 `[Audited]`、带 `ExpectedVersion`（05-06 D6）；变更历史由同一事务写入 `SystemSettingChange`。

### 6.3 读取

```csharp
// BuildingBlocks.Application（接口）/ Configuration（实现，经 Contracts 注册）
public interface ISettings
{
    ValueTask<T> GetAsync<T>(CancellationToken ct) where T : class, ISystemSetting<T>;   // 类型即键
}
```

- 读取经缓存（`Configuration:Settings`，一个键存全部已修改值，量很小），修改提交后失效并广播（D2），全实例毫秒级生效。
- 命令中读取的设置值作为普通输入参与计算；需要留痕时，由业务把“当时使用的值”写入业务数据本身。

### 6.4 与规则集的边界

| 用系统设置 | 用规则集（ADR-0017，延后事项） |
|---|---|
| 只关心“现在”的值 | 需要事后说明“这张单据当时按哪一版规则算的” |
| 修改后对之后的操作生效 | 规则有生效期、需要预先配置未来版本 |
| 例：通知收件人、默认分页大小、提醒提前天数 | 例：价格计算规则、审批流转条件 |

一个设置演变为需要追溯的规则时，迁移到规则集，并触发延后事项表中“版本化规则集”一项。

## 7. 偏好（FR-CFG-05，P2）

### 7.1 模型

ADR-0016：“内置 → 系统 → 角色 → 用户 + 角色”四层覆盖，重置只删除当前层，偏好不授予任何权限。

```csharp
[Preference("Sample.List.PageSize", "示例列表每页条数", Layers = PreferenceLayers.All)]
public sealed record SampleListPageSize(int Value) : IPreference<SampleListPageSize>
{
    public static SampleListPageSize Default => new(20);
    public static Result Validate(SampleListPageSize p) => p.Value is >= 10 and <= 200 ? Result.Success() : SampleErrors.PageSizeOutOfRange;
}
```

| 表 | 主要列 |
|---|---|
| `PreferenceValue` | `Id`、`Key`、`Layer`（`System` / `Role` / `UserRole`）、`RoleId` null、`UserId` null、`Value jsonb`、`ConcurrencyVersion`、审计字段；唯一 `(Key, Layer, RoleId, UserId)` |

- 解析：用户 + 当前角色层 → 角色层 → 系统层 → 代码默认值，取第一个有值的。
- `Layers` 声明哪些层允许设置（如某些偏好只允许系统层），默认全部层。值类型的约束与系统设置相同（第 6.1 节），由 `IPreference<T>` 保证默认值与校验。
- 修改系统层、角色层需要 `Configuration.Preference.Manage`；用户层由本人修改（`[AllowAuthenticated]`），只能改自己的。
- 重置：删除当前层的那一行。
- 偏好值只影响体验（列宽、默认筛选、页大小）；**架构测试**：授权、数据范围、资源策略相关代码不得依赖 `IPreferences`。

### 7.2 读取

- `GET /api/v1/configuration/preferences/me`：返回当前用户在当前角色下全部偏好的解析结果，前端启动时拉取一次，修改后更新本地。
- 缓存：系统层与角色层按标签缓存（`Configuration:Preferences:System`、`…:Role:{roleId}`）；用户层不缓存（每个用户一次查询，且只在启动时）。
- 修改不需要变更历史表（审计事件已足够，05-09 第 3 节）；偏好修改命令为 `[NotAudited("个人体验配置")]`，系统层与角色层的修改为 `[Audited]`。
- **前端偏好族**（F03 D5）：纯前端的展示偏好（表格列设置、外壳设置）不在后端逐个声明，而由框架声明两个偏好族：`Ui.Shell`（单键）与 `Ui.Table`（键为 `Ui.Table.{模块}.{页面}.{表格}`，各段为字母与数字，总长不超过 128）。后端只校验键格式、值为合法 JSON 对象且不超过 16 KB，不理解内容；内容由前端按版本化格式容错读取（F03 第 9.5 节）。四层覆盖、`Layers`、重置、权限、`[NotAudited]` / `[Audited]` 规则与普通偏好相同；`GET preferences/me` 一并返回。

## 8. 功能开关（FR-CFG-06，P2）

### 8.1 接入

- 使用 Microsoft Feature Management；开关名 `{模块}.{功能}`，常量在模块中声明。
- 端点或消息上声明 `[FeatureGate("Sample.NewImport")]`：关闭时端点返回 404（与“功能不存在”一致），后台入口不执行并记 Information。
- 开关只决定功能是否开放，**不授予权限**：开启后仍按权限点与数据范围授权（ADR-0016 第 3 节）。
- 前端经 `GET /api/v1/configuration/features` 取得当前对其开放的开关列表。

### 8.2 D6 开关的值存在哪里

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 现在只用配置文件 / 环境变量（Feature Management 的默认提供程序）** | `Kmic:Features:{名称}`，可用内置过滤器（时间窗、百分比） | 零额外表与界面；改开关走部署配置，有版本记录 | 改开关需要重启（D1） |
| B 现在就做数据库存储与管理界面 | 自定义 `IFeatureDefinitionProvider`，存 Configuration 模块 | 运行中切换 | 首期没有渐进发布的需求，是预建空能力（违反框架范围标准） |

- **决定（已确认，2026-11-04）**：A，并登记延后事项“数据库存储的功能开关”：触发条件为“出现需要在运行中切换、或按角色 / 用户灰度开放的功能”；已定约束：通过 Feature Management 的提供程序接口接入，业务代码中的 `[FeatureGate]` 与开关名不变。
- **取舍**：首期改开关要重启。

## 11. 测试要点

| 对象 | 必测场景 |
|---|---|
| Options | 非法值启动失败且列出全部问题；`[Required]` 缺失启动失败；`[Secret]` 在非开发环境来自 JSON 文件时启动失败；配置清单中密钥显示 `***`；模块注入 `IConfiguration` 被分析器拦截 |
| 缓存键 | 第一段不是本模块名时架构测试失败；Redis 前缀含环境 |
| 失效 | 提交后才失效（提交前并发读取不会把旧值重新写入）；回滚时不失效；两个实例下 A 修改后 B 立即读到新值（D2）；监听断开重连后 B 清空本地缓存 |
| 引用缓存 | 快照事件提交后对应 ID 失效；未提交（回滚）不失效；没有快照事件的聚合使用 `ReferenceCache` 启动失败 |
| 禁止项 | 模块中的可变静态字段、`IMemoryCache` 被拦截；缓存可变类型被拦截 |
| 字典 | 代码声明的类型登记与退役；编码不可修改；停用项不可选、历史显示 `[已禁用]`；`EnsureSelectable` 失败 422 |
| 系统设置 | 默认值生效；非法值 422；并发版本冲突 409；变更历史与修改同一事务；修改后全实例生效 |
| 偏好 | 四层解析顺序；重置只删当前层；只能修改自己的用户层；授权代码依赖 `IPreferences` 时架构测试失败 |
| 功能开关 | 关闭时端点 404、后台入口跳过；开启后仍要求权限点 |
