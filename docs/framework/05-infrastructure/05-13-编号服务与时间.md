## 1. 旧项目怎么做 → 新框架怎么做

| 问题 | 旧项目 | 新框架 | 章节 |
|---|---|---|---|
| 取号 | 查当前最大值或计数后 +1，拼接前缀；并发靠进程内 `static lock`，多实例会重号 | 模块内计数表 + 行锁，在业务事务内取号；唯一索引兜底 | 2 |
| 回滚 | 无约定 | 业务回滚，号码不消耗；不跳号 | 2.4 |
| 年度编号 | 专门的表（如 `Table_TeshuPingshenNum`） | 规则声明重置周期，新周期自动从 1 开始 | 2.2 |

## 2. 业务编号

### 2.1 声明

以下为示例（`Sample` 是演示模块，规则内容不代表任何真实单据）：

```csharp
// Sample.Application（示例）
public static class SampleNumberRules
{
    [NumberRule("SP-{yyyy}{MM}-{seq:4}", Reset = NumberReset.Monthly)]
    public const string Sample = "Sample.Sample";

    [NumberRule("RV-{yy}-{partition}-{seq:3}", Reset = NumberReset.Yearly, Partitioned = true)]
    public const string Review = "Sample.Review";        // 例：按产品线分别计数
}
```

| 占位符 | 含义 |
|---|---|
| `{yyyy}` `{yy}` `{MM}` `{dd}` | 取号时刻在**业务时区**下的日期部分 |
| `{seq:N}` | 序号，至少 N 位，左补零；超过 N 位时自然变长（不报错），达到 N 位上限的 90% 时记 Warning |
| `{partition}` | 分组键（D2），只能是大写字母与数字，长度 ≤ 10 |
| 其他字符 | 原样输出 |

| 重置周期 | 周期键 |
|---|---|
| `Never` | `-` |
| `Yearly` | `2026` |
| `Monthly` | `202611` |
| `Daily` | `20261104` |

- 规则名以本模块名开头、全局唯一，不超过 100 个字符；格式只能包含上述占位符，`{seq:N}` 有且只有一个（N 为 1～18），`Partitioned = true` 时有且只有一个 `{partition}`、否则不能有（启动校验）。
- 重置周期必须与格式中的日期段相容，否则不同周期会产生相同编号，启动校验拒绝：`Yearly` 要有年（`{yyyy}` 或 `{yy}`），`Monthly` 要有年和 `{MM}`，`Daily` 要有年、`{MM}` 和 `{dd}`。
- 编号字段在实体映射中声明唯一索引（ADR-0024 第 6 条），并登记错误码（05-03 第 7.3 节）。

### 2.2 计数表

每个使用编号的模块一张，由 `ApplyFrameworkTables()` 映射（05-03 第 8 节）：

`"{模块}"."NumberCounter"`

| 列 | 类型 | 说明 |
|---|---|---|
| `Rule` | `varchar(100)` | 规则名 |
| `PeriodKey` | `varchar(8)` | 周期键 |
| `PartitionKey` | `varchar(10)` | 分组键；不分组时为 `-` |
| `LastValue` | `bigint` | 最后发出的序号 |
| `UpdatedAt` | `timestamptz` | |

- 主键 `(Rule, PeriodKey, PartitionKey)`。
- 不清理：每个周期一行，量极小；保留下来也便于核对历史编号。

### 2.3 取号

```csharp
// BuildingBlocks.Application
public interface INumberGenerator
{
    // 只能在命令事务中调用；返回格式化后的编号
    ValueTask<string> NextAsync(string rule, string? partition = null, CancellationToken ct = default);
}
```

实现（一条语句，原子完成“创建或递增”，并对该行加锁直到事务结束）：

```sql
INSERT INTO "Sample"."NumberCounter" ("Rule", "PeriodKey", "PartitionKey", "LastValue", "UpdatedAt")
VALUES (@rule, @period, @partition, 1, @now)
ON CONFLICT ("Rule", "PeriodKey", "PartitionKey")
DO UPDATE SET "LastValue" = "NumberCounter"."LastValue" + 1, "UpdatedAt" = EXCLUDED."UpdatedAt"
RETURNING "LastValue";
```

- 周期键与日期段都由**同一个** `now`（`TimeProvider`，换算到业务时区）计算，避免跨午夜的请求中日期段与周期不一致。
- 不在命令事务中调用 → 抛异常（程序缺陷）。查询、Inbox 之外的后台入口同样要在命令中调用。
- 计数表只能经 `INumberGenerator` 访问（架构测试）。

### 2.4 D1 在命令中的什么时候取号

行锁持有到事务结束：同一规则的并发取号互相等待（ADR-0024 影响）。取号越早，锁持有越久。

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 处理器显式调用，约定放在处理器最后一步** | 处理器完成校验、构造聚合所需的其他数据后，最后取号并传给聚合的工厂方法 | 写法直接：聚合创建时就有编号，领域事件、快照事件、通知中都能使用编号；不需要额外机制 | 依赖“放在最后”的约定；取号之后领域事件处理与保存的时间仍在锁内（通常是毫秒级） |
| B 延迟到保存时分配 | 聚合先以“待分配”状态创建，保存拦截器在提交前最后一刻取号并回填 | 锁持有时间最短 | 处理器、领域事件处理器、快照事件构造时都拿不到编号；集成事件载荷中的编号要在拦截器中二次回填；复杂度明显上升 |

- **决定（已确认，2026-11-04）**：A。模块模板的“创建”命令示例按这个顺序写；评审清单列入“取号之后不再调用 Contracts 查询或其他耗时操作”。
- **理由**：本系统单据创建的并发量下，毫秒级的锁持有不构成瓶颈；B 为了缩短锁时间引入的“编号暂时为空”会扩散到事件、通知、日志中，代价大于收益。
- **取舍**：依赖约定；如果某个规则确实成为热点，按 ADR-0024 单独评估改用序列（接受跳号）。

### 2.5 D2 是否支持分组计数

旧系统部分编号带属性后缀（如按产品类别区分）。后缀可能只是显示，也可能每组要独立从 1 开始计数。

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 不支持；需要分别计数就声明多条规则 | 每个分组一条规则 | 计数表少一列 | 分组取值来自数据（如产品线编码）时，规则数量无法在代码中穷举；新增一个产品线要发版 |
| **B 支持可选的分组键** | 规则声明 `Partitioned = true`，取号时传入分组键，每个“规则 + 周期 + 分组”独立计数；不分组的规则分组键固定为 `-` | 分组取值可以来自字典或业务数据，新增分组不需要发版；计数表结构现在定下，以后不用给每个模块的框架表再做迁移 | 计数表多一列；分组键要做格式限制，防止任意字符串进入编号 |

- **决定（已确认，2026-11-04）**：B。分组键必须来自受控取值（字典编码、智能枚举编码），由调用方保证；框架只校验格式。
- **理由**：计数表是每个模块的框架表，事后加列要在所有模块生成迁移（05-03 第 8 节）；现在加一列的成本几乎为零。
- **取舍**：多一个参数与一条格式规则。

### 2.6 其他约定

| 项 | 约定 |
|---|---|
| 何时分配编号 | 业务决定（第二类）：创建时分配，或提交时分配（草稿无编号）。编号一经分配不可修改 |
| 删除 | 删除单据不回收编号 |
| 数据迁移 | 导入旧数据时保留旧编号；迁移脚本按旧数据中每个“规则 + 周期 + 分组”的最大序号初始化计数表（框架提供 `MigrationRunner` 维护命令 `numbers ensure-at-least`），保证新编号不与旧编号冲突 |
| 手工编号 | 不支持“用户自填编号并占用序号”；需要外部编号的业务，另设字段 |
| 测试 | `FakeTimeProvider` 控制周期；并发测试覆盖多实例 |

## 3. 时间

### 3.1 当前时间

- 统一使用 `TimeProvider`（ADR-0011 第 7 条），分析器禁止 `DateTime.Now`、`DateTime.UtcNow`、`DateTimeOffset.Now`、`DateTimeOffset.UtcNow`、`DateTime.Today`（框架基础设施中的少数位置豁免，如日志时间戳）。
- 领域层不取时间：处理器取 `time.GetUtcNow()` 作为参数传入聚合方法（05-02 第 7.3 节）。一个命令内只取一次，所有字段使用同一时刻。
- 租约、重试时间使用数据库时钟（05-07 第 6.1 节）；业务时间使用应用服务器时钟。生产主机必须启用 NTP 同步（写入运维手册）。

### 3.2 三种时间类型

| 含义 | C# | PG | JSON（05-06） | 例子 |
|---|---|---|---|---|
| 时刻 | `DateTimeOffset`（偏移 0） | `timestamptz` | `2026-11-04T02:30:00Z` | 创建、提交、审批时间 |
| 日期 | `DateOnly` | `date` | `2026-11-04` | 合同签订日、交货日期、截止日期 |
| 一天中的时间 | `TimeOnly` | `time` | `07:30:00` | 每日提醒时间 |
| 时长 | `TimeSpan` | `interval` | `"PT2H"`（ISO 8601 时长） | 有效期长度 |

- 判断标准：**“发生在某一刻”用时刻；“属于某一天”用日期。** 截止日期这类“到某天为止”是日期，不要存成当天 23:59:59 的时刻。
- `DateTime` 在模型中禁止使用（05-03 第 3.6 节）。

### 3.3 D3 业务时区工具的形态

按天、按月切分的逻辑（“今天的单据”“本月业绩”“截止日当天有效”）都需要业务时区。

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 静态全局 `BusinessTime.Zone`，启动时设置 | 任何地方（含领域层）直接调用 `BusinessTime.Today(now)` | 用起来最方便 | 全局可变状态（启动时设置一次）；测试中无法并行使用不同时区；领域层隐式依赖一个外部配置 |
| **B 应用层注入 `IBusinessCalendar`，领域层只接收已换算的值** | 处理器调用 `calendar.Today()`、`calendar.DayRange(date)` 等，把 `DateOnly` 或 UTC 区间作为参数传给聚合；领域层只比较值，不知道时区 | 与 `TimeProvider` 的做法一致：领域层纯粹、可测试；测试可替换时区验证跨午夜、月末等边界 | 领域方法需要多接收一个“业务日期”参数 |

- **决定（已确认，2026-11-04）**：B。
- **理由**：时区和当前时间一样是“环境输入”，ADR-0011 已经确定环境输入由应用层传入领域层。
- **取舍**：少数领域方法的参数多一个。

```csharp
// BuildingBlocks.Application
public interface IBusinessCalendar
{
    TimeZoneInfo Zone { get; }                                   // 配置 Kmic:BusinessTimeZone，默认 Asia/Shanghai
    DateOnly Today();                                            // 基于 TimeProvider
    DateOnly DateOf(DateTimeOffset instant);                     // 某一时刻在业务时区下属于哪一天
    UtcRange DayRange(DateOnly date);                            // [当天 00:00, 次日 00:00)，以 UTC 表示
    UtcRange Range(DateOnly from, DateOnly toInclusive);         // 日期段 → UTC 半开区间
    UtcRange MonthRange(int year, int month);
    DateTimeOffset StartOf(DateOnly date);                       // 当天 00:00 的 UTC 时刻
}

public readonly record struct UtcRange(DateTimeOffset Start, DateTimeOffset EndExclusive);
```

- 启动时校验时区 ID 可解析（容器镜像含时区数据，ADR-0022 已选 chiseled-extra）。
- 实现 `BusinessCalendar(TimeProvider, TimeZoneInfo)` 只做计算，放在 Application，宿主按配置传入时区。零点遇到夏令时跳变时：零点被跳过，这一天从跳变那一刻开始；零点出现两次，取较早的一次（业务时区默认 `Asia/Shanghai` 没有夏令时，这条只为配置成其他时区时结果仍然正确）。

### 3.4 区间约定

| 规则 | 说明 |
|---|---|
| 时刻区间一律半开 `[Start, EndExclusive)` | 不使用 23:59:59.999，避免精度问题与漏掉最后一毫秒 |
| 按日期筛选时刻列 | 先用 `IBusinessCalendar.Range` 转为 UTC 区间，再比较时刻列：`CreatedAt >= @start AND CreatedAt < @end`——可以使用索引 |
| 禁止在 `WHERE` 中转换列 | 不写 `(CreatedAt AT TIME ZONE …)::date = @date`：无法使用索引（代码评审；分析器提示 `ToBusinessDate` 出现在筛选条件中） |
| 列表查询的日期筛选参数 | 接口参数用 `DateOnly`（`createdFrom`、`createdTo`，含当天），查询处理器负责转换为区间 |
| 截止日期的比较 | 日期与日期比较：`Deadline >= calendar.Today()`，不转为时刻 |

### 3.5 SQL 中的时区

按天、按月**分组**统计时，必须在 SQL 中转换（ADR-0012 第 2 条）：

- 框架提供 EF 函数 `KmicFunctions.ToBusinessDate(DateTimeOffset)`，翻译为 `("Col" AT TIME ZONE @businessTz)::date`，时区作为参数传入（不写死字符串）。只用于 `GroupBy` / `Select`，不用于 `Where`（3.4）。
- 手写 SQL 使用 `IBusinessCalendar.Zone.Id` 作为参数。
- `ToBusinessDate` 由 EF 方法翻译器插件实现（原型 #6，`docs/framework/spikes/06-business-date.md`），生成 `CAST("Col" AT TIME ZONE '业务时区' AS date)`。时区来自部署配置、启动时已校验，翻译时**作为常量**写入 SQL（翻译器拿不到查询之外的参数值）；“不在代码中写死”的要求不变，同一进程内 SQL 文本相同。上海时区与含夏令时切换的时区，分组结果都与 .NET 换算一致。
- 报表模块（ADR-0013 模式 C）维护的统计数据，以业务日期（`DateOnly`）作为统计维度直接存储，查询时无需再转换。

### 3.6 D4 前端按什么时区显示时刻

接口中的时刻都是 UTC（05-06）。前端显示时：

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 浏览器本地时区 | 按用户电脑的时区显示 | 海外用户看到自己的本地时间 | 同一条记录在不同用户界面上可能显示为不同的日期；与后端按业务时区计算的“今天”“本月”不一致（报表按业务日期统计，界面却按本地日期显示） |
| **B 统一按业务时区显示** | 前端从 `me` 或启动配置取得业务时区，所有时刻按它显示；用户输入的日期时间也按业务时区解释 | 界面日期与后端的业务日期、报表口径完全一致；所有用户看到同一个时间 | 海外用户（如国外工厂）看到的是北京时间，需要在界面上标注时区 |

- **决定（已确认，2026-11-04）**：B。界面时间显示统一格式，必要时（用户浏览器时区与业务时区不同）在时间旁显示时区标记。
- **理由**：本系统的业务口径（日报、月报、截止日）都以业务时区为准；显示口径与计算口径一致，比“显示本地时间”更不容易引起误解。
- **取舍**：海外用户需要换算；以后若需要按用户时区显示，可作为偏好（05-10 第 7 节）增加，不影响后端。
- 后端提供：`GET /api/v1/identity/me` 响应包含 `businessTimeZone`（IANA ID）。

|---|---|
| 编号格式 | 各占位符；序号超过位数后变长；`Monthly` 规则格式不含 `{MM}` 时启动失败；非法分组键被拒 |
| 并发 | 多实例、多线程同时取同一规则，无重号、无跳号（Testcontainers 真实 PG） |
| 回滚 | 取号后命令失败，号码不消耗，下一次取到同一序号 |
| 周期 | 跨年、跨月、跨日（业务时区下）重置；UTC 已跨日而业务时区未跨日时周期不变（`FakeTimeProvider` 设为 UTC 15:59 / 16:00） |
| 分组 | 不同分组独立计数；同一分组共享 |
| 守卫 | 不在命令事务中取号抛异常；直接访问计数表被架构测试拦截 |
| 初始化 | `ensure-at-least` 之后新编号从最大值 + 1 开始；对已更大的计数不回退 |
| 时间 | 分析器拦截 `DateTime.Now` 等；`DayRange`、`MonthRange` 在月末、闰年、业务时区午夜附近正确；`ToBusinessDate` 翻译出带参数的 SQL；时区 ID 无效启动失败 |
