# ADR-0001 认证采用 JWT + 服务端会话

- 状态：已确认
- 日期：2026-11-03

## 背景

旧系统把用户 ID、角色等信息用 DES 加密后存在多个 Cookie 里，服务端没有会话，无法让会话主动失效，密码也是明文存储。

新系统的调用方目前只有自家 Vue 前端，以后可能增加手机 App 等客户端。

## 决策

1. **自建账号体系**：基于 ASP.NET Core Identity 管理用户、密码哈希、锁定和重置；JWT 的签发和刷新逻辑自行实现。
2. **令牌**：短期 Access Token（JWT）+ 长期 Refresh Token。Refresh Token 每次使用后换新（轮换）；发现旧令牌被重复使用时，作废该会话链。
3. **按客户端类型区分存放**：

   | 客户端 | Access Token | Refresh Token |
   |---|---|---|
   | Web | 前端内存 | `__Host-` 前缀的 HttpOnly + Secure + SameSite=Strict Cookie；登录、刷新、退出等写类认证请求校验可信来源（Origin）和 CSRF 请求头 |
   | App | App 内存 | 系统安全存储，通过响应体收发 |

4. **服务端会话表**：每次登录生成一条会话，记录客户端类型、设备、IP、当前角色、Refresh Token 哈希和状态。
5. **禁用立即生效**：JWT 中携带会话 ID（`sid`）。每个请求都从数据库读取会话状态和当前访问上下文（一次查询加载），**不跨请求缓存**（见 ADR-0016）。以下操作都会使会话立即失效：退出、改密码、禁用账号、管理员强制下线。
6. **单设备登录**：不限制，同一用户可在多台设备同时登录。
7. **当前角色**：保留“登录时选择当前角色”。当前角色存放在会话和 JWT 中；切换角色时在同一会话内重新签发令牌。
8. **权限不放进 JWT**：权限和数据范围按“用户 + 当前角色”从服务端缓存读取，授权变更后立即生效。
9. **有效期**：

   | 项 | Web | App |
   |---|---|---|
   | Access Token | 15 分钟 | 15 分钟 |
   | Refresh Token（滑动续期） | 7 天 | 30 天 |
   | 会话绝对上限（到期必须重新登录） | 30 天 | 90 天 |
   | 时钟偏差容忍 | 30 秒 | 30 秒 |

10. **签名**：RS256（RSA 2048 位），令牌头带 `kid`，支持密钥轮换；私钥放部署平台的 Secret，不进代码和镜像。
    - 选择理由：与 ES256 安全性都足够，性能差别可忽略；RS256 是 OpenID Connect 规定必须支持的算法，对接 App、第三方系统或换用标准授权服务器时兼容性最好。代价是令牌比 ES256 长约 200 字节。
11. **接口形式**：令牌响应和错误码按 OAuth2 习惯设计，以后需要第三方接入或单点登录时，可换用 OpenIddict 等标准授权服务器。
12. **不预置默认管理员**：首个账号、角色和初始授权由受控的运维命令显式初始化，系统中不存在内置的默认账号或默认密码。

## 影响

- 每个请求多一次走索引的会话与访问上下文查询。这是为了保证“禁用、改权限立即生效”在多实例下严格成立而接受的开销；压测证明成为瓶颈时，再评估短时缓存加版本校验。
- 刷新接口依赖 Cookie，需要 CSRF 防护和限流。
- 登录、刷新、发验证码接口单独限流。

## 补充说明（2026-11-04，05-04 认证与会话）

- **第 1 条“基于 ASP.NET Core Identity”的确切含义（05-04 D1）**：只使用 Identity 的组件——`IPasswordHasher<User>`（PBKDF2，支持旧哈希自动升级）和 Data Protection；**不使用** `UserManager`、`IdentityDbContext`、`IdentityUser` 和 `AspNetUsers` 等表。用户是 Identity 模块自己的 `User` 聚合，角色只有 ADR-0015 一套模型；锁定、重置流程自行实现（规则见 05-04 第 7 节）。
- **第 7 条“登录时选择当前角色”调整（05-04 D3）**：登录直接使用上次使用的角色（首次登录或该角色已失效时取第一个有效角色），界面明显显示当前角色并可随时切换；不再在登录时单独选择。
- **待决项的结论**：
  - 登录失败锁定（05-04 D4）：连续失败 10 次锁定 15 分钟，另按 IP 和账号限流；登录不做人机验证；管理员可手动解锁。
  - 验证码方式（05-04 D5）：不做图形验证码；人机验证使用云厂商服务，框架只定义 `IHumanVerification` 接口，目前只用于发送短信验证码；短信验证码登录的规则见 05-04 第 7.3 节。
  - 身份切换（05-04 D7）：默认只读，写操作需要额外的权限点 `Identity.User.ImpersonateWrite`；规则见 05-04 第 9 节。
