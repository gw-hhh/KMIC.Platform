# ADR-0005 使用源码生成式中介者处理横切逻辑

- 状态：已确认（库：martinothamar/Mediator 3.0.x，见 03-tech-selection.md 4.1）
- 日期：2026-11-03

## 背景

采用 CQRS 后，每个命令都需要经过校验、权限、事务、日志、领域事件分发等横切处理。旧系统中这些逻辑由每个 ashx 手写，经常遗漏。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 端点直接调用处理器，横切逻辑用 Endpoint Filter | 链路最短 | 横切逻辑与 HTTP 绑定，后台任务、事件处理等非 HTTP 入口无法复用 |
| MediatR | 生态最成熟 | 2025 年起转为商业许可；运行时反射 |
| **源码生成式中介者** | 开源许可；编译期生成分发代码，无反射开销；支持管道行为 | 生态比 MediatR 小 |

## 决策

使用**源码生成式中介者**。所有命令和查询都通过中介者分发，横切逻辑实现为管道行为，按固定顺序执行：

```mermaid
graph LR
    R[请求] --> L[日志与追踪] --> V[校验] --> Au[权限] --> T[事务] --> H[处理器]
    H --> E[领域事件分发 / Outbox 写入] --> C[提交]
```

- 查询不经过事务行为。
- 后台任务、集成事件处理等非 HTTP 入口，同样通过中介者执行，享有同一套横切处理。
