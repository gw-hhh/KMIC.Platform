# ADR-0016 可观测性、缓存、配置与多语言

- 状态：已确认（含待决项）
- 日期：2026-11-03

## 背景

旧系统：
- 只有文本日志，没有日志级别和追踪 ID；
- 缓存只在进程内，并存在静态字段缓存用户数据的写法；
- 配置、密钥、业务参数混在 Web.config 中，运行时写回配置文件导致应用重启；
- 提示文字直接写在代码里。

## 决策

### 1. 日志、链路追踪、指标

- 业务代码只依赖 .NET 标准的 `ILogger`，不直接引用 Serilog。
- **Serilog** 负责日志输出：容器中以 JSON 输出到标准输出，同时通过 OTLP 发送到可观测平台。
- **OpenTelemetry** 负责链路追踪和指标：
  - 追踪覆盖 HTTP、EF Core、HttpClient、中介者管道、后台任务、事件投递；
  - 指标包括请求量、耗时、错误率、数据库连接池、Outbox 积压量。
- 追踪 ID 贯穿 HTTP、后台任务、Outbox 和外部调用，所有日志自动带上，与错误响应中的 `traceId` 一致。
- 结构化日志规则：
  - 使用消息模板，禁止字符串拼接；
  - 敏感字段（密码、令牌、手机号等）自动脱敏，日志和追踪中不记录完整请求体、SQL 参数；
  - 高频日志使用源码生成的日志方法。
- 普通技术日志不逐请求写入业务数据库；关键审计与业务写入同一事务（见 ADR-0018）。
- 开发环境使用 Aspire 仪表盘。Domain、Application 不引用 Aspire，生产不要求部署 Aspire。
- **待决**：生产观测平台。倾向在 Docker 上自建 Grafana 一套（Loki / Tempo / Prometheus），由 OpenTelemetry Collector 统一接收。

### 2. 缓存

- **会话状态和授权上下文不跨请求缓存**：每个请求从数据库一次加载，保证“禁用、改权限立即生效”在多实例下严格成立（见 ADR-0001、ADR-0015）。按版本不可变的权限点集合可以缓存，见 ADR-0026。
- 读多写少的数据（字典、菜单、系统设置、偏好定义等）使用缓存。
- 业务代码使用 .NET 官方 **HybridCache**：单实例只用本地缓存；多实例时开启 Redis 二级缓存，只改配置，不改代码。
- 缓存键格式为 `模块:对象:标识`，按类别设置有效期，用标签批量失效。
- 被缓存的数据必须能容忍短暂的不一致；不能容忍的数据不进缓存。
- 禁止使用静态字段缓存与用户相关的数据，由架构测试检查。

### 3. 配置分类

“底层存储技术相似”不构成合并语义的理由，以下七类各自管理：

| 类型 | 解决什么 | 存储与管理 |
|---|---|---|
| 部署配置 | 连接、日志级别、开关等技术参数 | `appsettings.json`、`appsettings.{环境}.json`、环境变量；强类型 Options，启动时校验 |
| 密钥 | 数据库密码、JWT 私钥、SMTP 密码 | 开发用 User Secrets；生产见待决；不进代码仓库和镜像 |
| 字典 | 候选值 | 数据库，含启用、停用状态 |
| 系统设置 | 系统运行参数（如审批阈值、通知收件人） | 由代码注册定义（键、类型、范围、默认值）+ 当前值 + 变更历史；写入经过类型、范围、版本和权限检查 |
| 偏好 | 可继承的界面和体验配置 | 定义 + 统一值表 + 变更历史；按“内置 → 系统 → 角色 → 用户+角色”逐层覆盖；重置只删除当前层；偏好不授予任何数据或字段权限 |
| 规则集 | 会随时间变化、需要事后解释的业务规则 | 带版本，见 ADR-0017 |
| 功能开关 | 渐进发布 | Microsoft Feature Management；开关只决定功能是否开放，不授予权限 |

- 禁止运行时修改配置文件。
- 系统设置、偏好修改后通过缓存失效即时生效。
- 复杂的设置结构、自动生成设置界面等，等真实需求出现时再扩展，不预建空表。
- **待决**：生产密钥存储使用 Docker Secrets 还是独立密钥服务（如 Vault），取决于部署平台。

### 4. 多语言

- **预留，暂不实现**，默认中文。
- 错误码稳定且可枚举，前端可按错误码翻译。
- 后端面向用户的提示文字统一放在资源文件，通过 `IStringLocalizer` 读取，目前只有中文一份。
- 语言由请求头 `Accept-Language` 决定，默认中文。

## 影响

框架需要提供：
- 日志与 OpenTelemetry 的统一配置、脱敏处理；
- 访问上下文的单次加载查询；
- 缓存配置与键规范；
- Options 校验约定；
- 字典、系统设置、偏好的基础构件；
- 本地化资源约定。

## 补充说明（2026-11-04，随 05-10 确认）

- 部署配置启动时绑定并校验（`AddKmicOptions<T>` + `ValidateOnStart`），运行中不变，修改需重启；日志级别除外。模块不得直接读 `IConfiguration`（05-10 D1）。
- 多实例时各实例本地缓存的失效：`IAfterCommit.InvalidateTags` 在提交后失效本实例，并用 PG `NOTIFY` 广播到其他实例；监听断线重连后清空本地缓存。若 .NET 10 HybridCache 已内置跨实例失效，则改用内置机制（05-10 D2）。
- 字典类型由代码声明、字典项在界面维护，业务数据只存编码；接口只返回编码，前端翻译（05-10 D3、D4）。
- 跨模块引用名称由框架 `ReferenceCache` 统一缓存，随快照事件自动失效（05-10 D5）。
- 功能开关现在只用配置文件 / 环境变量；数据库存储登记为延后事项（05-10 D6）。

## 补充说明（2026-11-04，随 05-12 确认）

- 告警职责：应用只输出日志与指标，告警（含去重、静默）由观测平台规则发出；观测平台作为上线前置条件（05-12 D1）。
- 脱敏：框架定义数据分类（`Secret` / `Personal` / `Internal`），日志用源码生成方法与 `Microsoft.Extensions.Compliance.Redaction` 按分类脱敏，禁止整对象输出，属性名兜底；审计脱敏共用同一分类（05-12 D2）。
- 追踪：应用全量记录（`ParentBased(AlwaysOn)`），采样在 Collector 用尾部采样，错误与慢请求必保留（05-12 D3）。
- 请求日志：每请求一条摘要，不含请求体与查询串（05-12 D5）。

## 补充说明（2026-11-04，随 09 确认）

- 生产观测平台已定：自建 Grafana 栈（Grafana、Loki、Tempo、Prometheus），各应用主机运行 OpenTelemetry Collector 做尾部采样与转发；另用阿里云云监控对 ECS、RDS、ALB 配置基础告警，作为不依赖观测主机的独立告警通道（09 D6）。
- 生产密钥存储已定：阿里云 KMS 凭据管家；部署时由 `release` 执行机以 ECS 实例 RAM 角色读取，写入主机内存文件系统，以只读文件挂入容器；应用以“每个文件一个配置项”读取（09 D5）。不使用 Docker Compose 主机文件 secrets，也不自建 Vault。
- Redis 二级缓存首期不部署，触发条件登记在 00-README“延后事项”表（09 D7）。
