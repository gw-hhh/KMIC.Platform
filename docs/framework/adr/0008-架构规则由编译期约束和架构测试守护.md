# ADR-0008 架构规则由编译期约束和架构测试守护

- 状态：已确认
- 日期：2026-11-03

## 背景

旧系统名义上分了三层，但没有任何机制阻止越层，最终页面直接写 SQL 约 1180 处。架构规则如果只写在文档里，就一定会被打破。

## 决策

按约束强度分两级，**能用编译期约束的，不靠测试**：

1. **编译期约束（项目引用）**：
   - Domain 不引用任何框架；
   - Presentation 只引用本模块 Application；
   - 模块之间只能引用对方的 Contracts。
2. **架构测试（进入 CI，失败即阻断合并）**：
   - 依赖方向符合 ADR-0003、ADR-0004；
   - 模块之间不引用 Contracts 以外的类型；
   - SQL 和 EF 映射中不出现其他模块的 schema；
   - 一个工作单元只修改一个模块的数据；
   - 共享内核（框架构件）不包含业务概念；
   - 命名约定：命令、查询、处理器、端点、集成事件的命名后缀；
   - 匿名访问的端点必须显式标注，并输出清单供评审。

## 影响

- 架构测试是框架的一部分，随框架一起交付和维护。
- 新增规则时同步补充测试，规则文档和测试保持一致。
