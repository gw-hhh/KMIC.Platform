# ADR-0031 组织单元树归属 Identity 模块

- 状态：已确认
- 日期：2026-11-03
- 修订：ADR-0015 第 3 节“组织层级由框架定义抽象接口，由组织架构模块实现”

## 背景

数据范围中的“本组织”“本组织及下级”需要组织单元树。ADR-0026 要求每个请求用一次查询加载访问上下文，ADR-0006 禁止跨 schema 查询。如果组织单元树放在另一个模块中，这两条无法同时成立。

旧系统的组织维度（大区、大区分组、上下级）散落在用户表和多张关系表中，数据范围靠约 170 处手写条件。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **最小组织单元树放在 Identity 平台模块** | 一次查询加载访问上下文；数据范围不依赖任何业务模块 | Identity 模块范围变大 |
| 组织架构独立模块，Identity 维护副本 | 职责更细 | 副本最终一致，调整组织后数据范围延迟生效，与“立即生效”冲突 |
| 组织架构独立模块，每个请求同步调用 | 数据实时 | 每个请求多一次调用，打破一次加载 |

## 决策

1. Identity 平台模块保存**最小组织单元树**：组织单元 ID、上级、名称、状态，以及用户所属的组织单元。
2. 组织单元树是**授权的输入**，与角色、授予一样实时一致。组织调整后，下一个请求即按新结构计算数据范围。
3. 业务上对组织的其他描述（如大区分组、行业归属）由业务模块定义，通过 Identity 的 Contracts 引用组织单元 ID。
4. 组织单元树的维护界面归 Identity 模块。
5. 框架仍定义组织层级的抽象接口，供数据范围计算使用；实现位于 Identity 模块。

## 影响

- 组织调整需要校验：不能形成环，停用的组织单元下不能再分配用户。
- “本组织及下级”的计算需要层级查询，实现方式（递归查询、物化路径等）在 05 详细设计中确定。
