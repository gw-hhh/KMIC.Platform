# ADR-0024 业务编号采用计数表 + 行锁

- 状态：已确认；之后的修订见文末“修订记录”
- 日期：2026-11-03

## 背景

ADR-0009 确定业务编号（报价单号、合同号等）与主键分离，由框架的编号服务生成，但没有确定实现方式。

旧系统的做法是查当前最大值或计数后加 1，再拼接前缀，并发安全依赖进程内 `static lock`。多实例部署时会重号；业务回滚时号码的处理也没有约定。

## 备选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **计数表 + 行锁** | 按“规则 + 周期”一行计数，在业务事务内 `UPDATE … RETURNING` 取号 | 与业务同一事务，回滚不消耗号码、不跳号；按年 / 月重置简单 | 同一规则的并发取号在该行上串行，锁持有到事务结束 |
| PG 序列 | 每个规则一个 sequence | 并发性能最好 | 事务回滚也会消耗号码（跳号）；按周期重置需要额外管理 |
| 预分配号段 | 每个实例一次领取一段号码 | 高并发 | 跳号、实例重启丢号、编号不按时间顺序 |

## 决策

1. 框架提供编号构件，采用**计数表 + 行锁**。
2. 计数表放在使用它的模块 schema 内，不建全局编号表（符合 ADR-0006）。
3. 取号在业务事务内完成：业务提交，号码才生效；业务回滚，号码不消耗。取号在处理器中显式调用，约定放在处理器最后一步，以缩短行锁持有时间（05-13 D1）。
4. 计数行按“规则 + 周期键”区分（如 `Quotation` + `2026`），新周期第一次取号时自动创建。计数表 `NumberCounter` 主键 `(Rule, PeriodKey, PartitionKey)`，以 `INSERT … ON CONFLICT DO UPDATE … RETURNING` 一条语句取号；支持可选分组计数（05-13 D2）。
5. 编号格式（前缀、日期段、序号位数、重置周期）由业务模块声明，框架只负责格式化和取号。声明方式为 `[NumberRule("格式", Reset = …, Partitioned = …)]`，占位符为业务时区下的 `{yyyy}{yy}{MM}{dd}`、`{seq:N}`（超过 N 位自然变长）、`{partition}`；重置周期须与格式中的日期段相容（启动校验）（05-13 第 2.1 节）。
6. 编号字段加唯一索引，作为最后一道防线。
7. 迁移旧数据时由 MigrationRunner 维护命令 `numbers ensure-at-least` 按旧编号最大值初始化计数（05-13 第 2.6 节）。

## 影响

- 同一规则的取号互相等待，业务事务必须保持短小，取号应尽量放在事务末尾。
- 单据创建的并发量远低于行锁成为瓶颈的量级；如果以后某个规则确实成为热点，可以单独评估改用序列（接受跳号）。
- 需要并发测试：多实例同时取号不重号、回滚不跳号、跨周期重置。
