# ADR-0027 平台能力由平台模块与模块内框架表承载

- 状态：已确认
- 日期：2026-11-03

## 背景

账号与会话、附件、通知、字典与设置、任务记录等能力与业务无关、由框架提供，但都需要存数据。ADR-0006 规定任何数据都必须属于某个模块的 schema，且一个事务只能修改一个模块的数据。

旧系统的做法是公共表任意读写，日志库甚至存放被页面读取的业务快照。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 共享表（BuildingBlocks 自带公共表） | 实现最简单 | 违反 ADR-0006，重演旧系统 |
| **平台模块 + 模块内框架表** | 符合 ADR-0006；同事务要求得到满足；平台模块以后可直接独立 | 平台模块要按业务模块的标准开发；部分框架表在每个 schema 中各有一份 |
| 全部放进各模块 | 模块完全自包含 | 同一能力重复多份 |

## 决策

**划分标准**：是否必须与业务数据同一事务提交。必须同事务的，放在每个模块自己的 schema 中；其余的，做成平台模块。

### 1. 模块内框架表

由框架统一映射、模块模板生成，每个模块 schema 中各有一份：

- Outbox、Inbox（ADR-0007、ADR-0028）
- 审计事件（ADR-0018）
- 业务历史（ADR-0018）
- 幂等记录（ADR-0011）
- 编号计数表（ADR-0024）

### 2. 平台模块

平台模块与业务模块结构相同（5 个项目、独立 schema、Contracts），只能通过 Contracts 和集成事件被使用：

| 平台模块 | 内容 |
|---|---|
| Identity | 账号、会话、角色、权限点、授予、数据范围配置、组织单元树（ADR-0031）、安全事件 |
| Files | 附件元数据、文件生命周期、上传配额 |
| Notifications | 模板及版本、发送记录、站内消息、非生产捕获存储 |
| Configuration | 字典、系统设置、偏好 |
| Operations | Quartz 表、任务执行记录、后台作业记录、死信与积压管理视图、审计汇总 |

### 3. 协作约定

- **附件关联**：“附件属于哪个业务对象”的关联记录放在业务模块自己的 schema 中，与业务同事务；Files 模块只管文件本身。下载由业务模块的端点先校验资源策略，再通过 Files 的 Contracts 读取文件流。
- **审计查询**：审计事件写在各模块 schema 中，同时发布集成事件，由 Operations 模块汇总为统一的审计查询视图（最终一致）。
- **平台模块不是共享内核**：BuildingBlocks 中仍然不得出现任何业务概念或表（ADR-0008）。

## 影响

- 首期需要按完整标准开发 5 个平台模块。
- ADR-0020 中“附件元数据表 + 附件关联表，所有模块共用”修订为：元数据归 Files 模块，关联归各业务模块。

## 补充说明（2026-11-04，随 05-08 确认）

- **后台作业表**改为模块内框架表 `"{模块}"."BackgroundJob"`（与幂等、Outbox / Inbox 同类），提交作业与业务数据同一事务；Operations 不存作业，只通过各模块的框架存储接口提供“我的任务”和管理列表的汇总视图。
- Operations 的内容相应改为：Quartz 表、定时任务配置覆盖值（`ScheduledJobSetting`）与执行记录（`ScheduledJobRun`）、消息路由表（05-07）、后台作业与死信积压的汇总视图、审计汇总。
- 原因：作业表若在 Operations，提交作业的命令要跨两个模块写入，违反 ADR-0006 第 4 条。详见 05-08 D6。

## 补充说明（2026-11-04，随 05-09 确认）

- 模块内框架表中不再有“审计事件”：审计事件随业务事务写入本模块 Outbox，由 Operations 订阅写入 `AuditLog`，作为唯一长期存储；第 3 节“审计查询”以此为准（05-09 D3）。
