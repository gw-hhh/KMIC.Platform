# ADR-0014 接口层约定

- 状态：已确认；之后的修订见文末“修订记录”
- 日期：2026-11-03

## 背景

旧系统接口的问题：
- 每个模块用一个巨型 ashx，以 `Ctype` 参数分发几十个动作；
- 返回格式沿用 layui 约定 `{code, msg, count, data}`，并且永远返回 HTTP 200；
- 没有错误码、没有版本、没有接口文档；
- 筛选条件常以字符串拼接到 SQL。

新系统前端是 Vue 3，以后可能增加手机 App，客户端无法强制同步升级。

## 决策

### 1. 端点组织（REPR 模式）

- 一个接口一个类，包含请求、端点、响应。端点类实现框架自研的 `IEndpoint` 接口，启动时自动发现并注册。
- 同一模块的端点挂在同一路由组下，统一设置要求登录、OpenAPI 分组标签等。
- 端点只做三件事：接收请求 → 交给中介者 → 由框架把 Result 转成 HTTP 响应。
- 不引入 FastEndpoints、Carter 等第三方端点框架。

### 2. 路由风格

- 格式为 `/api/v{版本}/{模块}/{资源复数}`，如 `/api/v1/sales/quotations`；模块名视为稳定契约（05-06 D3）。
- 模块名、资源名使用小写，多个单词用连字符连接。
- 动作型操作作为子路径，如 `POST /api/v1/sales/quotations/{id}/submit`。

### 3. 响应格式：HTTP 语义 + ProblemDetails

- 不使用 `{code, msg, data}` 统一包装。
- 成功时响应体直接是数据；失败时返回 ProblemDetails（RFC 9457）。

| 情况 | 状态码 |
|---|---|
| 查询成功 | 200 |
| 创建成功（返回新资源 ID） | 201 |
| 无返回内容的操作成功 | 204 |
| 校验失败 | 400 |
| 未登录或会话失效 | 401 |
| 无权限 | 403 |
| 不存在 | 404 |
| 并发冲突、状态冲突、幂等键冲突 | 409 |
| 前置条件不满足（暂不出现，见第 4 节 `currentVersion`） | 412 |
| 请求体过大 | 413 |
| 不支持的媒体类型 | 415 |
| 违反业务规则 | 422 |
| 请求过于频繁 | 429 |
| 依赖服务暂不可用 | 503 |
| 系统错误 | 500 |

### 4. 错误响应格式

ProblemDetails 标准字段之外，增加以下扩展字段：
- `code`：错误码，来自错误目录（ADR-0010）。状态码只表示大类，客户端行为依据 `code`；
- `traceId`：追踪 ID；
- `errors`：仅在校验失败时出现，按字段路径（支持嵌套和数组下标）列出 `{ code, message }`，不暴露数据库列名和内部异常；
- `currentVersion`：仅在并发冲突时出现，返回最新的并发版本号。并发版本通过请求体 `expectedVersion` 传递，不使用 `If-Match`（05-06 D6）；
- `retryable`：是否可以原样重试（如 503 可重试，422 不可重试）。

`type` 使用 `urn:kmic:error:{错误码}`；客户端只依据 `code`（05-06 D5）。

```json
{
  "type": "urn:kmic:error:Quotation.AlreadySubmitted",
  "title": "报价单已提交",
  "status": 422,
  "detail": "报价单 QT-2026-000123 已提交，不能重复提交",
  "code": "Quotation.AlreadySubmitted",
  "traceId": "00-4bf92f35...-01"
}
```

### 5. 分页、排序、筛选

- **页码分页**（`page`、`pageSize`）为默认方式，用于后台列表；`pageSize` 有上限（默认 200）。响应带 `totalCountExact`；列表可声明上限计数（默认上限 10,000），超过时前端显示“10,000+”（05-06 第 6.1 节）。
- **游标分页**（`after`、`limit`）用于 App 流式列表、大批量导出和数据同步接口。
- 筛选使用每个列表单独定义的**强类型查询参数**，不提供 OData 等通用动态筛选。
- 排序格式为 `sort=-createdAt,number`（`-` 表示倒序）。每个列表声明可排序字段的白名单，不在白名单内的字段返回 400。

### 6. API 版本

- 使用 URL 路径版本，从 `v1` 开始。不引入 `Asp.Versioning`，版本即路由组（05-06 D4）。
- 向后兼容的改动（新增字段、新增接口）不升版本。
- 破坏性改动才出新的主版本，且只有发生破坏性变化的端点才升版本。旧版本保留一段时间并标记废弃，返回 `Deprecation` / `Sunset` 头。
- 请求中的未知字段返回 400；因此部署顺序为先后端、后前端（05-06 D7）。

### 7. OpenAPI

- 使用 .NET 内置的 OpenAPI 文档生成，界面使用 Scalar。
- 前端根据 OpenAPI 文档自动生成 TypeScript 类型和请求代码，生成工具在技术选型时确定。
- 文档只在开发和测试环境开放。
- CI 检查 OpenAPI 文档完整性：每个操作、参数、字段、枚举值都要有说明（05-06 第 7.1 节）。

### 8. JSON 序列化

| 项 | 规则 |
|---|---|
| 序列化库 | System.Text.Json |
| 属性命名 | 小驼峰 |
| 枚举、智能枚举 | 字符串 |
| 强类型 ID | 字符串 |
| 时刻 | 带时区的 ISO 8601（UTC） |
| 日期 | `yyyy-MM-dd` |
| 金额 | 数字；超过 15 位有效数字的场景单独改用字符串 |
| 空值 | 输出 `null`，不省略字段 |

## 影响

框架需要提供：
- `IEndpoint` 自动注册与路由组约定；
- Result 到 HTTP 响应的转换；
- ProblemDetails 扩展；
- 分页与排序模型、排序白名单校验；
- 版本化配置；
- OpenAPI 配置与 JSON 转换器（智能枚举、强类型 ID）。
