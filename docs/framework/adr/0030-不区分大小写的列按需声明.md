# ADR-0030 不区分大小写的列按需声明

- 状态：已确认
- 日期：2026-11-03

## 背景

旧系统依赖 SQL Server 排序规则 `Chinese_PRC_CI_AS`，字符串比较默认不区分大小写。PostgreSQL 默认区分大小写。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **默认区分；需要的列使用 ICU 非确定性排序规则** | 等值比较、唯一索引不区分大小写，查询写法不变 | 模式匹配（`LIKE`）的支持有限制 |
| `citext` 扩展 | 简单 | 需要扩展；非 ASCII 大小写规则不完整；类型特殊 |
| 规范化影子列 | 不依赖特殊特性 | 每个字段多一列，写入必须同步 |

## 决策

1. 字符串列**默认区分大小写**。
2. 需要不区分大小写的列（如账号、邮箱、编号、外部系统代码），通过框架提供的映射约定显式声明，使用迁移中统一创建的 ICU 非确定性排序规则（大小写不敏感）。
3. 不使用 `citext`。
4. 编码规范给出这类列上模糊查询的标准写法。

## 待确认

- PG 18 在非确定性排序规则下对 `LIKE` 的支持范围，实施时用测试验证；不支持的场景按编码规范的替代写法处理。

## 补充说明（2026-11-06，随原型 #5 验证）

- 上一条待确认关闭：PG 18 在非确定性排序规则下**支持 `LIKE`**（不区分大小写），**不支持 `ILIKE`**；`und-u-ks-level2` 不区分大小写、区分重音。模糊匹配仍统一用 06 第 11.2 节的框架函数（`COLLATE "C"` + `ILIKE`），已验证两类列写法与结果一致。见 `docs/framework/spikes/05-text-matching.md`。
- 排序规则的创建位置待原型 #5 D1 确认（Npgsql 的 `UseCollation` 不支持带 schema 的名称）。
