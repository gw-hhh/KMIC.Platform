# 在另一台机器上继续开发

仓库里的代码、文档、配置已经足够从零开始；下面是 git 之外要自己准备的东西，以及哪些东西不会跟着走。

## 1. 取得代码

```text
git clone https://github.com/gw-hhh/KMIC.Platform.git
```

- 这是私有仓库，需要有访问权限的 GitHub 账号。
- 远端只有 `main` 一个分支。阶段 1 的原型代码保留在标签 `archive/spike/*` 上（`git fetch --tags` 取得），结论已写进各设计文档。
- 克隆下来的根目录就是项目根。**用 Claude Code 时在这个目录里打开**，它会自动读取根目录的 `CLAUDE.md`（项目规则、命名、工作约定）。不需要旧仓库 `kelong.web`。

## 2. 本机要装的东西

| 东西 | 要求 | 用在哪里 |
|---|---|---|
| .NET SDK | `global.json` 固定为 10.0.403（只升补丁版，不用预览版） | 编译、测试 |
| Docker | Docker Desktop 或其他能运行 Linux 容器的引擎，要先启动 | 数据库测试用 Testcontainers 起 `postgres:18.6`；密钥扫描用 Gitleaks 镜像 |
| 本地工具 | 克隆后运行一次 `dotnet tool restore`（`dotnet-ef` 10.0.14） | 生成迁移 |
| Node.js | 24.22.2 | `check.cs` 里的拼写检查用 `npx cspell`；以后前端也用 |
| pnpm | 11.28.9（前端阶段才需要；12 在 Windows 上遇到 `packageManager` 字段会崩溃） | 前端 |

## 3. 验证环境是否可用

```text
dotnet run scripts/check.cs -- --fix-only
dotnet run scripts/check.cs
```

- 第一条只修能自动修的（BOM、CRLF、summary 标签各占一行），几秒钟；第二条是完整检查：后端的编码、注释格式、用词、格式、编译（警告即错误）、测试、依赖漏洞，前端的类型、代码检查、格式、单元测试、构建、端到端（Playwright，假后端），最后是密钥扫描和拼写。全部通过约 12 分钟；当天第一次运行或依赖变了时，依赖漏洞扫描另需约一分半。
- 开发中途用 `dotnet run scripts/check.cs -- --fast`：只跑静态检查和单元测试，一两分钟；提交前仍要跑一次完整检查。
- 只跑前端端到端：`web` 目录下 `pnpm test:e2e`（第一次先 `pnpm exec playwright install chromium`）。
- 跑检查期间不要改源码。

## 4. 已知需要注意的地方

- **MinIO 测试镜像。** `MinioFixture` 默认用 `kmic/minio:RELEASE.2025-10-15T17-29-55Z`。MinIO 社区版不再发布官方镜像，这个镜像从源码构建，新机器上先构建一次（几分钟）：`docker build -t kmic/minio:RELEASE.2025-10-15T17-29-55Z docker/minio`。
- **`src/Hosts/Kmic.Api/Properties/launchSettings.json`** 是 Visual Studio 生成的本地启动配置，没有提交；新机器上会自己重新生成。
- **CI 暂停自动运行。** GitHub Actions 只能手动触发（待办 T-01、T-18），日常以本机的 `check.cs` 为准。在 Linux 上手动运行一次完整检查，是阶段 2 验收的最后一项（T-18）。

- **Docker 命名约定。** 现在整个系统都在测试阶段，容器、卷统一写成 `kmic-test-用途`，用途是 `postgres`、`minio` 这类一眼能看懂的词；名字只能用英文字母、数字和短横线，不能用中文。
  - 手工起的：容器 `kmic-test-postgres`、`kmic-test-minio`，卷建议叫 `kmic-test-postgres-data`、`kmic-test-minio-data`。
  - 自动化测试起的：容器 `kmic-test-postgres-xxxxxxxx`、`kmic-test-minio-xxxxxxxx`，结尾的随机后缀避免同时跑两次时重名；都带 `com.docker.compose.project=kmic-test` 标签，Docker Desktop 里会归成一组。测试时还会出现一个 `testcontainers-ryuk-…`，是 Testcontainers 用来清理容器的，名字改不了。
  - 自己构建的镜像写成 `kmic-服务:标签`，如 `kmic-api:dev`。
  - 卷建好后不能改名。早期手工建的 `kmic_pg18_data`、`kmic_minio_data` 沿用旧名字，重建时改成上面的写法。
- **新生成的迁移文件**：先 `dotnet run scripts/check.cs -- --fix-only` 去掉 BOM 和 CRLF，再跑检查。

## 5. 不在仓库里的东西

| 东西 | 在哪里 | 影响 |
|---|---|---|
| 旧系统源码（`kelong.web`，WebForms） | 原机器 `C:\开发项目\kelong.web`，**没有版本管理** | 只在需要再读旧代码时才要；已经提炼的结论在 `docs/legacy/` 与各模块设计文档的“旧系统对照”里 |
