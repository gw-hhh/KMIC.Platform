# 在另一台机器上继续开发

仓库里的代码、文档、配置已经足够从零开始；下面是 git 之外要自己准备的东西，以及哪些东西不会跟着走。

## 1. 取得代码

```text
git clone https://github.com/gw-hhh/KMIC.Platform.git
```

- 这是私有仓库，需要有访问权限的 GitHub 账号。
- 默认分支 `main` 是全部工作成果。`spike/*` 是阶段 1 的原型分支，不合入主干，结论在 `docs/framework/spikes/` 与 `docs/frontend/spikes/`，原型代码只在对应分支上。
- 克隆下来的根目录就是项目根。**用 Claude Code 时在这个目录里打开**，它会自动读取根目录的 `CLAUDE.md`（项目规则、命名、工作约定）。不需要旧仓库 `kelong.web`。

## 2. 本机要装的东西

| 东西 | 要求 | 用在哪里 |
|---|---|---|
| .NET SDK | `global.json` 固定为 10.0.403（只升补丁版，不用预览版） | 编译、测试 |
| Docker | Docker Desktop 或其他能运行 Linux 容器的引擎，要先启动 | 数据库测试用 Testcontainers 起 `postgres:18.6`；密钥扫描用 Gitleaks 镜像 |
| 本地工具 | 克隆后运行一次 `dotnet tool restore`（`dotnet-ef` 10.0.14） | 生成迁移 |
| Node.js | 24.22.2 | `check.cs` 里的拼写检查用 `npx cspell`；以后前端也用 |
| pnpm | 11.28.9（前端阶段才需要；12 在 Windows 上遇到 `packageManager` 字段会崩溃） | 前端 |

## 3. 验证环境是否可用

```text
dotnet run scripts/check.cs -- --fix
dotnet run scripts/check.cs
```

- 第一条先规整换行与 BOM（Windows 上有些工具按 CRLF 写文件）；第二条是完整检查：编码 → 注释格式 → 用词 → 格式 → 编译（警告即错误）→ 测试 → 依赖漏洞 → 密钥扫描 → 拼写。全部通过约 12 分钟。
- 最近一次完整检查（`0774f5a`）的测试数是 1057 个，全部通过。之后只改了文档。
- 跑检查期间不要改源码。

## 4. 已知需要注意的地方

- **MinIO 测试镜像。** `MinioFixture` 默认使用 `kmic/minio:RELEASE.2025-10-15T17-29-55Z`。这个镜像是开发机上从 MinIO 源码自行构建的，**不在任何镜像仓库里，构建方法也没有写进仓库**，所以在新机器上依赖它的测试会拉不到镜像。两种办法：
  - 把原机器上的镜像搬过去：`docker save kmic/minio:RELEASE.2025-10-15T17-29-55Z -o minio.tar`，新机器上 `docker load -i minio.tar`；
  - 或设置环境变量 `KMIC_TEST_MINIO_IMAGE` 指向一个能拉到的 MinIO 镜像（测试容器以 root 运行，所以默认非 root 的镜像也能用）。
  
  谁来固定这个镜像的来源（推到公司的镜像仓库，或写入构建说明），目前没有定，属于待办。
- **`Kmic.AppHost`（Aspire 本地编排）** 在原开发机上一启动就崩溃（0xC0000005），没有验证过，见待办 T-26。换机器后可以顺便试试能不能正常启动。
- **`src/Hosts/Kmic.Api/Properties/launchSettings.json`** 是 Visual Studio 生成的本地启动配置，没有提交；新机器上会自己重新生成。
- **CI 暂停自动运行。** GitHub Actions 只能手动触发（待办 T-01、T-18），日常以本机的 `check.cs` 为准。在 Linux 上手动运行一次完整检查，是阶段 2 验收的最后一项（T-18）。

## 5. 不在仓库里的东西

| 东西 | 在哪里 | 影响 |
|---|---|---|
| 旧系统源码（`kelong.web`，WebForms） | 原机器 `C:\开发项目\kelong.web`，**没有版本管理** | 只在需要再读旧代码时才要；已经提炼的结论在 `docs/legacy/` 与各模块设计文档的“旧系统对照”里 |
| 表格参考项目 `vue-table` | 原机器 `Documents/程序/vue-table` | 只在做前端业务表格时需要（`docs/frontend/F02`、`F07`） |
| Claude Code 的记忆（用户偏好、进度笔记） | 原机器 `~/.claude/projects/…/memory/` | 不会跟着仓库走。项目规则在 `CLAUDE.md` 里，进度在 `docs/implementation/`、`docs/modules/`、`docs/framework/00-README.md` 里，足够接着做；想保留记忆可以把这个目录整个复制过去（目录名由项目路径编码而来，路径不同时需要对应改名） |
| 本机 PostgreSQL 18 的手工调试库、Docker 里的镜像与容器 | 原机器 | 都可以重建，不是源数据 |
