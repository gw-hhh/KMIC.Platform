# 本地运行

在自己的机器上把整个后端跑起来：数据库在 Docker 里，Api 直接用 `dotnet` 启动。不需要阿里云、Gitea 这些外部服务。

## 前提

- Docker Desktop 已经启动。
- 装了 .NET 10 SDK。

## 一条命令启动

```
dotnet run scripts/dev.cs -- up
```

脚本依次做这些事，已经做过的会跳过：

1. 启动数据库容器 `kmic-test-postgres`（本机端口 5433）。容器不存在就新建，命名规则见 `换机器继续开发.md` 的“Docker 命名约定”。
2. 建数据库 `kmic_local`，建运行账号 `kmic_app`（密码随机生成）。
3. 执行全部模块的迁移。
4. 第一次运行时创建管理员账号 `admin`，密码随机生成。
5. 生成本机用的令牌签名密钥。
6. 启动 Api，同时跑后台处理，地址 `http://localhost:5080`。

启动后可以看：

- 接口文档：`http://localhost:5080/scalar`
- 健康检查：`http://localhost:5080/health/ready`

按 Ctrl+C 停止 Api。数据库容器会继续运行，下次再 `up` 直接连上。

## 第一次登录

- 账号 `admin`，密码在仓库根目录的 `.local/dev.json` 里（`AdminPassword`）。
- 第一次登录后必须先改密码，改之前其他接口都返回 403 `Common.PasswordChangeRequired`。
- 登录：`POST /api/v1/identity/auth/login`，请求体 `{ "account": "admin", "password": "…", "clientType": "app" }`，响应里有 `access_token`。
- 改密码：`POST /api/v1/identity/auth/change-password`，要带 `Idempotency-Key` 请求头。
- 之后的请求带上 `Authorization: Bearer <access_token>`。

## 其他命令

| 命令 | 作用 |
|---|---|
| `dotnet run scripts/dev.cs -- status` | 看数据库容器、数据库、管理员的状态 |
| `dotnet run scripts/dev.cs -- reset` | 删掉本机数据库 `kmic_local`，下次 `up` 重新迁移并建管理员 |

## 文件放在哪

仓库根目录的 `.local/` 文件夹，已经加进 `.gitignore`，不会提交：

- `dev.json`：生成的密码（数据库、运行账号、管理员）。
- `keys/`：令牌签名密钥。
- `files/`：上传的文件（本地存储）。

整个删掉再 `up`，就是一套全新的本机环境（数据库里的数据要用 `reset` 单独删）。

## 本地环境的特点

- 开发环境下 Api 启动时会自己执行迁移，用的是数据库管理账号；日常访问用受限的运行账号 `kmic_app`。
- 示例模块 `Sample` 是开启的，用来演示标准写法。
- 通知默认只“捕获”不真发：邮件和短信的内容可以在 `GET /api/v1/notifications/captured` 里查看。
- 脚本不用 `Kmic.AppHost`（Aspire）。它在原来的开发机上一启动就崩溃，见待办 T-26。
