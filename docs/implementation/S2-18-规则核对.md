# S2-18 06 规则总表核对

- 日期：2026-11-12
- 范围：`06-coding-standards.md` 第 15 节规则总表（15.1 自定义分析器、15.2 禁用 API、15.3 内置规则、15.4 架构测试），对应阶段 2 退出标准 3：“06 规则总表中每条规则都有对应的分析器测试或架构测试”
- 方法：逐条找到让违规变成失败的机制，并指出证明它会失败的测试；找不到的写明原因。这里的测试名都在仓库里，不凭记忆

## 1. 结论

| 部分 | 结果 |
|---|---|
| 15.1 自定义分析器（21 个编号） | 全部有“报告”与“不报告”两类用例 |
| 15.2 禁用 API | 三份清单全部生效，每个符号由架构测试核对能解析；效果由构建保证（一处违规就是编译错误） |
| 15.3 内置与 Meziantou 规则 | 全部在 `.editorconfig` 里设为 error（或明确关闭），随每次构建生效，没有单独的测试 |
| 15.4 架构测试 | 本节第 5 项列出的 4 条没有机器检查（评审或随第一个业务模块补），其余全部有架构测试，并且每条规则都有故意违规的样例证明规则会失败（`BadSamples`） |

## 3. 15.2 禁用 API

清单：`BannedSymbols.txt`（全部项目）、`BannedSymbols.Tests.txt`（测试项目）、`BannedSymbols.Modules.txt`（`src/Modules/**`）。`tests/Kmic.ArchitectureTests/BannedSymbolsTests` 核对：每个符号都能解析成唯一的符号（写错一个字符规则就悄悄失效）、每份清单都接进了构建、模块清单包含约定的符号。

| 规则 | 清单 |
|---|---|
| `DateTime.Now` 等、`Guid.NewGuid()`、`new HttpClient()`、`Task.Wait` / `Result` / `GetAwaiter().GetResult()` | 全局 |
| 测试里的 `Task.Delay`、`Thread.Sleep` | 测试 |
| `IConfiguration`、`IMemoryCache`、`IDistributedCache`、`Task.Run`、`new Thread`、`ThreadPool.QueueUserWorkItem`、服务定位、`IgnoreQueryFilters`、`FromSqlRaw` / `SqlQueryRaw` / `ExecuteSqlRaw`、`Results.Problem` / `StatusCode` | 模块 |
| Application 中的 `DbContext` 写入 API | 依赖方向规则：Application 拿不到 Infrastructure 的 `ModuleDbContext`，只有 `IQueryable` 形式的查询入口，没有写入 API（`DependencyRuleTests`） |
| 已选定能力的替代库（MediatR、AutoMapper、Moq、FluentAssertions 等） | 禁用包（`Directory.Build.targets` 的 KMIC0001），随构建失败 |

## 4. 15.3 内置与 Meziantou 规则

全部在根目录 `.editorconfig` 设为 error（IDE0016～IDE0360 的现代写法 39 条按 06 第 3.4 节），CA1716、RS1033、MA0097 按 06 的限定范围关闭，CA2007、MA0004 关闭。`TreatWarningsAsErrors` 与 `MSBuildTreatWarningsAsErrors` 为 true，所以任何一条违规都是编译失败。本表列出的规则编号逐个在 `.editorconfig` 里核对过存在。

## 5. 15.4 架构测试

测试在 `tests/Kmic.ArchitectureTests`（105 个）。“违规样例”指 `Violations/BadSamples.cs` 里对应的类型，测试断言规则会报出它。

| | 聚合根属性不得是其他聚合根 | `HygieneRuleTests.AggregatesReferenceEachOtherOnlyById` |

| | 状态机 `Build()` 成功 | `StructureRuleTests.EveryAggregate_InitializesItsStateMachine`（触发每个聚合的类型初始化） |
| 05-02 | 命令 / 查询命名；消息为 `sealed record` | `NamingRuleTests.Messages_AreNamedAndShapedAsAgreed` |

| | 命令响应是收据 | `StructureRuleTests.CommandResponses_AreReceipts`：结构（属性类型、嵌套对象、逐条收据）；语义（是不是本人可取回的最小信息）由评审 |

## 6. 这次核对带来的改动

- 新增架构规则 14 条（`StructureRules`、`InjectionRules`），每条有违规样例；新增读方法体的辅助 `Support/IlCalls`（`[BypassesDataScope]`、缓存值两条规则用它）。
- Sample 的 `SubmitSpecimenCommand` 补 `[Idempotent]`：05-02 规定提交类命令要幂等，原来的实现既没标也没写豁免原因，架构规则暴露了这个不一致。
