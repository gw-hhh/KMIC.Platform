# 协作交接记录

多个 AI 或人轮流改这个项目时，在这里留下交接信息。Claude Code 每次继续前先读本文，再用 `git log`、`git diff` 核对实际改动；摘要和实际改动不一致时以实际改动为准。

## 写法

- 每次工作一节，倒序，最新的在最上面。
- 开始工作时先写一节（状态“进行中”），再动手；结束时更新状态和提交范围。中途断了也能知道做到哪里。
- 本文和代码改动放在同一个提交里。
- 提交号写真实的哈希（`git log --oneline` 取），不要凭记忆写。
- 只在自己的那一节里写，不改别人写的历史记录。
- 不提交、不推送，除非用户明确说；改动放在单独的分支，不直接改 `main`。

## 每节的格式

```text
## 日期 时间 做了什么（一句话）

- 工作者：哪个 AI（模型名）或人
- 分支：
- 基线提交：开始时 main 的位置
- 提交范围：起点..终点
- 状态：进行中 / 已完成 / 中断（写清停在哪里）
- 改动摘要：每条一句话，写清哪些模块或文件夹
- 与设计的差异：没有，或列出（同时登记到 docs/framework/00-README.md 待决事项表，标“待用户确认”）
- 检查结果：dotnet run scripts/check.cs 是否全过；没跑的写“未运行”和原因
- 没做完的事 / 需要用户确认的事：逐条写
- 是否已合并到 main：否（等用户确认）
```
