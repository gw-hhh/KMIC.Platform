## 1. D1 Vue 版本

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A Vue 3.5（当前稳定版 3.5.4x）** | 稳定；全部生态库都已适配 | 没有 Vapor 模式的性能提升 |
| B Vue 3.6 候选版 + Vapor 模式 | 不经虚拟 DOM 渲染，性能更好 | 3.6 截至 2026-10 仍在候选版（RC）；Vapor 模式与组件库、表格库的兼容性尚无大规模验证 |

- **决定（已确认，2026-11-04）**：A；3.6 稳定后按常规升级（对现有代码兼容），Vapor 模式等组件库与 VXE Table 明确支持后再评估局部使用。
- **理由**：业务后台的性能瓶颈在表格与数据量，不在框架渲染层；稳定性优先。
- **取舍**：暂不享受 Vapor 模式的性能提升。

## 2. D2 构建与运行环境

| 项 | 建议 | 说明 |
|---|---|---|
| 构建工具 | **Vite 8** | 2026-03 稳定，底层改为 Rolldown（Rust），官方称构建快 10～30 倍；Vue 插件照常使用 |

## 3. D3 TypeScript

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A 严格模式 + vue-tsc 支持的最新 TypeScript（6.x）** | Vue 单文件组件的类型检查完整可用 | 类型检查速度不如原生版 |
| B 直接用 TypeScript 7（原生版，2026-07 发布，快约 10 倍） | 速度快 | 7.0 还没有稳定的编程接口，vue-tsc、typescript-eslint 等工具暂时不能使用它 |

- **决定（已确认，2026-11-04）**：A；TypeScript 7 等 Vue 工具链与 typescript-eslint 支持后升级。
- **理由**：Vue 项目的类型检查必须经过 vue-tsc；速度可以等，正确性不能等。
- **取舍**：暂时用较慢的类型检查。

## 4. D4 组件库

新前端的表单、弹窗、选择器、日期、上传、菜单、提示等通用组件来自组件库；业务表格另选（D5）。审核时用户明确：Element Plus 的外观不符合期望，倾向 Ant 一类的风格。因此本项同时比较**外观**与**长期维护**。

| 选项 | 外观 | 维护状态（2026-11 核实） | 优点 | 缺点 |
|---|---|---|---|---|
| **A TDesign Vue Next（腾讯）** | 现代、干净的企业风格，与 Ant 同一类 | 腾讯维护；约两周一版（1.20.10 为 2026-10-15）；约 374 位贡献者；未处理问题 658 个 | 外观与维护保障兼顾；设计规范完整；有设计语言一致的手机端组件库，以后做手机端可沿用 | 外观不完全是 Ant；社区资料少于 Element Plus |
| B Antdv Next | 即 Ant Design v6 的外观与交互，信息密度高 | 社区维护，非 Ant 官方；约两周一版（1.7.1 为 2026-10-27）；约 46 位贡献者；未处理问题仅 3 个 | 外观最符合“Ant 风格”；Vben 已支持 | 无企业背书，长期维护依赖社区（Ant Design Vue 4 即因维护者精力不足停滞）；但问题处理及时 |
| C Element Plus | 朴素 | 成熟、社区最大 | 最稳妥 | 外观不符合期望；改皮肤需要较多设计工作 |
| D Arco Design Vue（字节） | 好看 | 积压 700+ 未处理问题，活跃度存疑 | — | 不选：维护状态存疑 |
| E Ant Design Vue 4 | Ant 风格（v4） | 2024-11 后基本停止更新 | — | 不选：维护停滞 |
| F Naive UI / PrimeVue | — | 维护放缓或近期发版不明 | — | 不选 |

- **决定（已确认，2026-11-04）**：B Antdv Next。用户偏好 Ant Design 的外观；维护数据核实合格（见上表）。原建议为 A TDesign Vue Next。
- **理由**：在“外观”与“5～10 年的维护保障”之间最平衡；企业持续投入是组件库最重要的风险控制。
- **取舍**：外观不完全是 Ant 的样子。
- **补充（2026-11-04，按 GitHub 实际数据修正）**：两者都在活跃维护（数据见上表，取自 GitHub 接口）。先前“Antdv Next 核心约 4 人”来自捐助页面，实际贡献者约 46 人，问题处理及时；两者在维护上都合格。用户偏好 Ant 风格，因此 **B 同样可接受**，最终由用户按外观选择。
- **如果更看重 Ant Design 的外观**：B 也可以，代价是没有企业背书。无论选 A 还是 B，框架都设一层**组件适配层**（表单项、弹窗、提示、选择器等经框架组件使用），业务页面不直接依赖组件库的细节，以后更换的成本可控。
- **说明**：最终的视觉效果很大程度取决于外壳设计（D6）与统一设计变量（D9），组件库主要决定按钮、表单、弹窗等部件的样子。用户对比两个官网后选定 Antdv Next（[TDesign Vue Next](https://tdesign.tencent.com/vue-next/overview)、[Antdv Next](https://www.antdv-next.com/)）。

## 5. D5 业务表格

旧系统 307 个页面用表格，其中 175 个用固定列、43 个行内编辑、18 个合计行（F01 第 1.2 节）。

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A VXE Table 4（MIT）** | 专门面向业务表格：固定列、行内编辑、合计行、虚拟滚动（大数据量）、列设置、复制粘贴、树形表格；与任何组件库并用 | 自身体积较大；样式需要与组件库的主题变量对齐；官方另有部分收费的扩展插件，必须确认所用功能都在 MIT 范围内（`待确认`） |
| B 组件库自带表格 | 风格一致、无额外依赖 | 行内编辑、大数据量虚拟滚动、合计等需要大量自行封装；大数据量性能不足 |
| C AG Grid 社区版 | 功能强、性能好 | 企业功能收费（开源核心 + 商业功能），违反 03 选型原则 |

- **决定（已确认，2026-11-04）**：A；所有数据列表统一使用 VXE Table，经框架封装为一个“业务表格”组件（列定义、分页、`allowedActions`、偏好保存在封装内统一处理）；组件库表格只用于很小的展示型表格。
- **理由**：表格是本系统使用最多、要求最高的组件，选专门的表格库；统一封装后，业务页不直接依赖 VXE 的细节。
- **取舍**：多一个大依赖；主题对齐工作；`待确认`：阶段 0 锁定版本时核对 VXE 的收费插件边界，框架只使用 MIT 部分。

## 6. D6 应用外壳

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 以 Vben Admin 5 为底座 | 在 Vben 的工程（monorepo）上开发 | 布局、标签、菜单、偏好、权限、请求封装开箱即用 | 工程结构、请求、权限、状态的写法都要按 Vben 的方式来，与本系统已定的后端契约（`allowedActions`、ProblemDetails、幂等、版本冲突、刷新加锁）和“页面实例”模型需要大量改造；升级要跟随 Vben 的节奏 |

## 7. D7 服务端数据的获取与缓存

| 选项 | 状态 | 优点 | 缺点 |
|---|---|---|---|
| **A TanStack Query（Vue）v5** | 成熟，跨框架广泛使用 | 请求去重、缓存、失效、重试、取消、后台刷新都现成；文档与社区成熟 | 概念较多；需要与“页面实例”的生命周期配合（F03 设计） |

- **决定（已确认，2026-11-04）**：A。用于读取类请求（列表、详情、字典、`me`、引用信息）；写入经框架的请求层（幂等键、版本、结果未知处理），写入成功后按标签失效相关查询。
- **理由**：成熟度优先；缓存与竞态是容易写错的部分，不值得自建。

|---|---|---|
| **A 设计变量（CSS 变量）+ SCSS** | 颜色、字号、间距、圆角、阴影、层级、动效集中定义一次，同时映射到组件库与 VXE 的主题变量；浅色 / 深色切换只换变量 | 布局类样式要自己写（提供少量布局组件弥补） |
| B 再引入 Tailwind CSS 4 / UnoCSS | 布局写得快；Vben 使用 | 与组件库主题变量形成两套样式体系，需要额外桥接；模板中样式类过长 |

- **决定（已确认，2026-11-04）**：A。
- **理由**：后台系统的视觉一致性主要来自组件库与表格的主题，统一的设计变量比原子类更关键；一种能力只用一套方案（03 原则 3）。
- **取舍**：页面布局多写一些样式。

## 10. D10 质量与测试工具

| 用途 | 建议 | 说明 |
|---|---|---|
| 代码检查 | **ESLint**（扁平配置）+ eslint-plugin-vue + typescript-eslint | Oxlint 速度快，但只检查 `.vue` 文件中的脚本部分，模板规则仍需 ESLint；以后可作为补充加速 |

| 类型检查 | vue-tsc | 见 D3 |

- **取舍**：ESLint 比 Oxlint 慢；以准确为先。
