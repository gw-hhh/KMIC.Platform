# F01 旧前端盘点与前端需求

- 状态：已确认（2026-11-04）
- 日期：2026-11-04
- 范围：只盘点与前端框架有关的部分，不展开业务页面；需求只列框架能力
- 依据：`docs/legacy/01-legacy-analysis.md` 第 1.3、6 节；旧代码 `Web/Manage` 的使用量统计（2026-11-04，只读）；后端 05 系列契约

## 1. 旧前端怎么做的

### 1.1 技术与形态

| 方面 | 旧系统 |
|---|---|
| 页面形态 | aspx 输出 HTML 壳 + 内联 `<script>`；约 290 个页面用 jQuery / layui 表格请求同目录的 `GetJson.ashx?Ctype=xxx`；约 74 个页面仍用 GridView 等服务端控件，31 个依赖 PostBack |
| 外壳 | layuiadmin 风格的 `Manage/Index.aspx`：左侧菜单 + iframe 多标签页；页面之间通过 `parent.layui`、`window.parent` 互相调用（刷新列表、关闭标签、打开新标签） |
| 主要库 | layui 2.4.5；jQuery 以 1.7.2 为主，共 7 个版本混用（同一页面可能引两个）；约 50 个页面局部用 Vue 2.6 |
| 其他库 | formSelects / xm-select 多选下拉；ECharts（多版本）；uploadify；Lodop 打印；city-picker 省市选择；remodal、SuperSlide |
| 接口格式 | layui 约定 `{code, msg, count, data}`，`code = 0` 成功，部分接口 `code = 1` 表示失败或登录超时；没有错误码，前端只能按 `msg` 文字判断 |
| 权限 | 页面入口 `BasePage.PermissionID` 校验，无权限时输出 `alert` 后 `history.back()`；按钮权限以数字 ID 硬编码 |
| 业务逻辑 | 金额计算、税率换算、锁定提示、“非客户”判断等写在页面内联脚本或 `Jisuan.js`、`AmountInput.js`、`LockTishi.js` 等公共脚本中 |
| 导出 | 大部分在后端 `Daochu*.ashx` 生成 Excel；少量 layui 前端导出 |
| 构建 | 无前端构建；脚本与样式直接引用，无版本号，缓存靠手工刷新 |

### 1.2 页面能力的使用量（`Web/Manage`，按文件计）

| 能力 | 使用的文件数 | 对新前端的含义 |
|---|---|---|
| layui 表格 `table.render` | 307 | 列表是主体，表格组件是前端框架中最重要的一块 |
| 表格固定列 | 175 | 多列宽表普遍，必须稳定支持左右固定列 |
| 表格行内编辑 | 43 | 明细录入类页面需要可编辑表格 |
| 表格工具栏 | 240 | 列表普遍有批量操作入口 |
| 表格合计行 | 18 | 需要合计 / 汇总行 |
| 多选下拉 | 182 | 多选、远程搜索选择器是高频组件 |
| 日期控件 | 178 | 日期与日期范围（与 05-13 业务时区口径一致） |
| 上传 | 136 | 附件上传是高频能力（05-11 上传档案） |
| ECharts 图表 | 26 | 看板与统计页需要图表 |
| Lodop 打印 | 2 | 少量打印（属于按需能力） |

### 1.3 主要问题

1. **iframe 多标签 + `parent` 调用**：页面之间隐式耦合，标签间状态没有隔离与生命周期管理，关闭标签不提示未保存内容。
2. **多版本库混用、无构建**：没有依赖管理与版本控制，没有类型检查，没有测试。
3. **前端承担业务规则**：金额、状态、锁定判断散落在脚本中，前后端各算一遍且可能不一致。
4. **接口无错误码、无 HTTP 语义**：一律 200 + `code`，前端只能比较文字。
5. **权限只在入口**：按钮靠数字 ID，与后端实际授权不同源。
6. **重复提交只靠前端防连点**（后端 ADR-0011 已用幂等解决，前端需配合传递幂等键）。

## 2. 新前端框架要提供的能力

优先级与后端 02 相同：**P0** = 第一个业务模块（试点）开发前必须具备；**P1** = 首期上线前必须具备；**P2** = 按需。

### 2.1 外壳与工作区（SHELL）

| 编号 | 需求 | 优先级 | 依据 |
|---|---|---|---|
| FE-SHELL-01 | 应用外壳：侧栏菜单、顶栏、面包屑、多标签工作区、内容容器；设计参照 Vben Admin | P0 | 用户要求；F02 D6 |
| FE-SHELL-02 | 多标签之间状态隔离：每个标签的查询条件、分页、表格、表单、滚动、请求互不影响；切换标签不丢失编辑内容 | P0 | 旧系统 iframe 多标签的使用习惯 |
| FE-SHELL-03 | 未保存保护：关闭标签、切换角色、退出、刷新浏览器时，存在未保存或“保存结果未知”的内容须提示 | P0 | 旧系统问题 1 |
| FE-SHELL-04 | 当前角色明显显示，可随时切换；切换后旧页面的请求结果不得作用于新角色 | P0 | 05-04 D3 |
| FE-SHELL-05 | 模拟身份时显著提示实际操作人，只读模拟时禁用写操作 | P1 | 05-04 D7 |
| FE-SHELL-06 | 新版本发布后，旧页面加载代码块失败时，提示并由用户确认“重新加载应用”（保护未保存内容），不自动刷新 | P1 | 前端发版的常见问题 |
| FE-SHELL-07 | 偏好：主题（浅色 / 深色）、侧栏、表格密度等，按 05-10 的偏好四层保存 | P1 | 05-10 第 7 节 |
| FE-SHELL-08 | 全局搜索菜单（命令面板），只显示有权限的入口 | P2 | — |

### 2.2 路由、菜单与权限（AUTH）

| 编号 | 需求 | 优先级 | 依据 |
|---|---|---|---|
| FE-AUTH-01 | 一份类型化的路由目录，统一定义路径、标题、图标、菜单归属、所需权限点、页面组件；菜单、面包屑、标签都由它生成 | P0 | 05-05 D3（菜单由前端路由声明权限点） |
| FE-AUTH-02 | 权限点常量从后端导出的 TypeScript 文件引用，不手写字符串 | P0 | 05-05 第 3.1 节、05-06 第 7.2 节 |
| FE-AUTH-03 | 按钮可见与可用只依据详情接口返回的 `allowedActions`，不在前端重新推导业务规则 | P0 | 05-05 第 7 节 |

### 2.3 认证与请求（API）

| 编号 | 需求 | 优先级 | 依据 |
|---|---|---|---|
| FE-API-01 | 类型化请求：类型由 OpenAPI 生成，请求经 openapi-fetch，不手写接口类型 | P0 | 03 第 4.5 节 |
| FE-API-02 | 访问令牌只放内存；刷新令牌在 `__Host-` Cookie 中；刷新请求带 `X-Requested-With: kmic`；多个浏览器标签页并发刷新时跨标签页加锁 | P0 | 05-04 第 3.3～3.5 节、D2 |
| FE-API-03 | 错误统一按 ProblemDetails 处理：按 `code` 而不是文字判断；字段错误按 `errors` 的路径定位到表单字段；`retryable` 决定是否提示重试 | P0 | 05-06 第 4.3 节 |
| FE-API-04 | 幂等：需要幂等的写操作自动生成并携带 `Idempotency-Key`；超时或断线时“结果未知”，用**原键**重试或查询，不换新键 | P0 | ADR-0011 第 10 条 |
| FE-API-05 | 并发版本：修改请求带 `expectedVersion`；409 版本冲突时提示刷新并保留用户的输入 | P0 | 05-06 D6、05-03 第 6 节 |
| FE-API-06 | 读请求可取消；切换标签、重新查询、关闭页面后，迟到的响应不得覆盖当前页面 | P0 | 多标签工作区的常见问题 |
| FE-API-07 | 429（限流、`Common.TooBusy`、`Identity.LoginThrottled`）按 `Retry-After` 显示可等待时间 | P1 | ADR-0022、R01 M5、05-04 D4 补充 |
| FE-API-08 | 后台作业：202 后跟踪作业进度、取消、下载结果文件 | P1 | 05-08 第 6 节 |

### 2.6 不在前端框架范围

| 事项 | 归属 |
|---|---|
| 业务规则（金额计算、状态判断、锁定规则） | 后端领域层；前端只显示后端结果，必要时做同口径的即时预览 |
| 具体业务页面 | 各业务模块设计 |

## 3. 已确认的范围（2026-11-04）

| 事项 | 结论 |
|---|---|
| 浏览器 | Chrome、Edge（最新两个版本）；不考虑其他浏览器 |
| 屏幕适配 | 桌面端响应式：窗口变窄时侧栏收起、查询条件折行，宽表格保留横向滚动；不设“最小宽度”要求。具体断点在 F03 外壳设计中定 |
| 手机端 | 首期不做专门适配；以后需要时再单独设计 |
| 微信登录 | 不考虑（旧系统 `WeiXinLoginApi` 不迁移） |
