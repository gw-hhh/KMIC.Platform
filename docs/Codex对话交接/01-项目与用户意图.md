## 用户明确表达的质量要求

用户的原话包括。

> 我这个是新项目，对代码质量要求比较高，优先级第一的就是代码质量，代码实现，代码注释，代码排版，要求高级。而不是只要能实现就行。

> 另外给我补充的是，设计的好点，灵活点之类的，架构层面之类的。

据此，讨论中形成了以下要求。

- 技术选型优先采用当前稳定的新版本和合适的新方案，例如 .NET 10。
- 新版语言特性能让代码更清晰、更简洁或更可靠时，优先使用。
- 架构职责和模块边界清晰，依赖关系明确。
- 对已经明确或经常发生的业务变化，预留合适的扩展空间，让改动集中在相关模块。
- 抽象和分层应有实际价值，复杂度与需求相匹配。
- 命名准确、排版统一，关键业务约束和容易误解的设计决定应有简明说明。
- 功能实现之外，也要检查代码是否容易理解、测试和修改。需要取舍时，优先长期可维护性。

新版本的具体可用性需要在实际选型时核实。这些要求没有把预览版本作为默认选项。

## C# 私有字段命名

用户问过 C# 私有字段的一般命名。Codex 回答常用写法为下划线加 camelCase，`readonly` 字段同样适用。

```csharp
private readonly ILogger<OrderService> _logger;
private int _retryCount;
```

参数和局部变量一般使用 `retryCount`，公共属性一般使用 `RetryCount`。这是当时的通用写法说明，实际开发仍须核对当前项目的命名约定。
