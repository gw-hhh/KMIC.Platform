# Codex 展示过的注释改写示例

以下保留此前对话中展示的 30 个拟改例子，便于新会话理解用户希望看到的表达方式。这些示例均停留在预览阶段，实际修改前仍需核对当前实现与适用规则。

源码路径均相对 KMIC.Platform 仓库根目录。短注释只展示正文。

## 示例标本的短注释

来源为 `src/Modules/Sample/Kmic.Sample.Domain/Specimens/Specimen.cs`。

| 编号 | 原文 | 拟改为 | 重点 |
|---|---|---|---|
| 1 | 负责人，创建者 | 负责人 | 当前创建流程将创建者设为负责人，但两个概念不能直接等同 |
| 2 | 所属组织，数据范围按它判断 | 所属组织，用于判断数据访问范围 | 说清“数据范围”的含义 |
| 3 | 创建草稿，状态的起点同时写入业务历史 | 创建草稿并记录初始状态 | 去掉难懂的压缩表达 |

## 示例 8 移除附件

原文。

```csharp
/// <summary>
/// 移除附件，返回被移除的那个，调用方据此解除文件的关联
/// </summary>
/// <param name="attachmentId">附件</param>
```

拟改为。

```csharp
/// <summary>
/// 移除附件
/// </summary>
/// <param name="attachmentId">附件 ID</param>
/// <returns>成功时返回被移除的附件，供调用方解除文件关联</returns>
```

返回值说明有实际用途。调用方会从返回的附件获取文件 ID，再解除文件关联。

## 示例 26 下载权限与返回结果

`IFileDownloads` 的原说明重复强调业务授权，并把错误状态一起塞在类头。

原文。

```csharp
/// <remarks>
/// Files 没有自己的下载端点，下载权限完全继承业务对象：业务的下载查询先完成业务对象的授权、确认关联存在，
/// 再用它取下载信息。<b>调用方必须先完成业务对象的授权</b>，知道文件 ID 就能取到下载信息。
/// 文件状态由这里判断，业务不用重复：只有已关联的文件可以下载，被彻底删除的返回 410 Files.Purged，
/// 还没登记完的返回可重试的 Files.NotReady，其余按不存在处理
/// </remarks>
```

接口上的约定拟整理为。

```csharp
/// <remarks>
/// 调用方必须先校验业务对象的访问权限，并确认该对象关联了此文件。
/// 文件状态由本接口检查，只有已关联的文件允许下载
/// </remarks>
```

`GetAsync` 方法上拟补充返回结果。

```csharp
/// <returns>
/// 文件的下载信息。已彻底删除时返回 Files.Purged，对应 HTTP 410。
/// 尚未就绪时返回可重试的 Files.NotReady，其余不可下载的状态按不存在处理
/// </returns>
```

权限责任、文件关联检查和失败结果都要保留。文件位于 `src/Modules/Files/Kmic.Files.Contracts/IFileDownloads.cs`。

## 应保留的现有注释

| 注释 | 保留理由 |
|---|---|
| 内容的 SHA-256，小写十六进制 | 含义和格式明确 |
| 并发版本号，修改时作为 expectedVersion 带回 | 调用方需要遵守的约定 |
| 返回第一个失败，全部成功时返回成功 | 准确说明方法行为 |
| 标题、状态、附件 | 用于接口文档或数据库说明时有实际用途 |

## 从这些例子提炼的尺度

优先修正歧义和描述不准的问题，再处理长句和重复说明。保留必要术语、关键约束和有用的短注释。实际执行时按当前项目规则安排 XML 标签，避免为了调整说明位置增加大量空壳注释。
